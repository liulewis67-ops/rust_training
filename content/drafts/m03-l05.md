# M03-L05：实验——内存任务清单

下载[实验起始项目 ZIP](./public/m03-l05-starter.zip)，解压到新的空目录后阅读其 `README.md` 和公开契约测试。起始项目先有一个状态解析类型错误；修正后，查询实现仍不完整，公开测试会检出新增任务无法查回。完成实现后再验证状态变更、非法状态和不存在的任务契约。

## 实验目标

- 用 `Vec<Task>` 在内存中保存任务；通过公开结构体和方法提供受控操作。
- 按递增编号新增任务，并查询当前列表中的任务。
- 将精确状态文本转换为 `TaskStatus`，然后更新指定任务的状态。
- 区分状态更新成功、任务不存在和状态文本无效；失败更新不能暗中修改任务。
- 从原始 ZIP 快照开始修复、运行测试并重新解压，记录版本和文件哈希。

## 行为契约

- 新列表从任务编号 1 开始；成功添加后返回该编号，并将任务状态设为 `Todo`。
- 查询已有编号返回 `Some(&Task)`，不存在的编号返回 `None`；编号、标题和状态通过只读方法读取。
- 状态文本只接受大小写敏感的 `"todo"`、`"doing"`、`"done"`，分别映射到同名枚举变体。
- `set_status` 对合法状态文本先做解析：未知状态文本返回 `UpdateOutcome::InvalidStatus`，且不修改列表；合法状态对应的编号不存在时返回 `TaskNotFound`；目标存在时更新并返回 `Updated`。
- 非法状态优先于编号查找。例如对不存在的编号传 `"blocked"`，结果仍为 `InvalidStatus`。
- 操作只更新内存，不读写文件、不联网，也不使用第三方 crate。

## 实验步骤

1. 在空目录解压 ZIP，记录其 SHA-256、`starter-manifest.json`、`rustc --version` 和 `cargo --version`。
2. 先运行 `cargo check --offline` 并保存初始诊断；定位 `parse_status` 中状态值与返回类型不一致的问题。
3. 修正编译错误后运行 `cargo test --offline`。观察失败的查询测试，再实现从 `Vec<Task>` 查找任务，避免只改到能编译。
4. 逐条核对公开测试：新增后查询、三个状态转换、无效文本不改状态，以及合法状态下不存在的编号。
5. 检查一种合理但错误的修复：把任意未知文本默认为 `Todo`。确认公开测试会拒绝它，且正式实现不能把输入错误伪装成成功更新。
6. 运行 `cargo fmt -- --check`、`cargo check --offline` 和 `cargo test --offline`；保留公开测试文件不变。
7. 把原始 ZIP 解压到新的空目录，核对 manifest 中每个文件哈希与版本；从重置副本再复现编译修复和测试。这只验证作者侧快照可重复读取，不等同平台重置服务。

## 起始快照中的预期故障

起始 `parse_status` 的合法状态 arm 返回 `TaskStatus`，但函数要求 `Option<TaskStatus>`，因此 `cargo check` 应因 E0308 失败。仅将已知 arm 包成 `Some` 后，查询方法仍会对每个编号返回 `None`，公开查询与后续更新测试失败。另一种错误修复是把任意未知状态映射为 `Todo`，公开非法状态用例应检出它。

## 提示

1. 先逐项比对 `parse_status` 的返回类型和每个 `match` arm。
2. 查询时遍历不可变借用；命中后返回当前 `Task` 的引用，没有命中时返回 `None`。
3. 更新先解析状态文本，再遍历可变任务；找到目标后立即更新并返回对应枚举结果。
4. 不要在遍历期间另行修改整个 `Vec`；只改当前任务的状态字段。
5. 公开 API 使用私有字段，调用方通过 `TaskList` 方法进行添加、查询和变更。

## 重置与验收边界

保留发行的起始 ZIP 不变。重新开始时解压到另一个空目录，核对 ZIP 哈希、快照版本和清单文件哈希；不要用修复后的源码覆盖起点。R1 平台还须保护公开测试和起始快照，并提供版本化重置。本机压缩包与重新解压只能验证作者侧重复性，不能证明隔离、防篡改或平台重置能力。
