# M24-L04 三道短练习

## 修复：让纠正措施可追踪

starter 中 `validate_action` 接受空白 owner 和缺少完成证据的行动项。补上 title、owner role、due date、priority 与 evidence ID 的非空校验，按稳定顺序返回具体错误。

**合同：**合法行动项不变地接受；任一必需字段缺失/空白即失败；不虚构负责人或完成证据。

**提示：**“团队以后留意”不是带有 owner 和完成定义的行动项。

## 实现：稳定排列维护候选

实现 `rank_maintenance`，按 customer impact 降序、repeat likelihood 降序、effort 升序、item ID 升序排列；不修改候选，也不删除重复项。这个公开排序合同只是练习模型，真实团队需要确认各风险类型权重。

**公开检查：**覆盖主排序键、逐层 tie-break、重复 ID 的稳定结果和空列表。

**提示：**在输出副本上排序，并显式写出所有 tie-break。

## 设计评审：复盘中的事实与假设

检查一段写着“worker 部署导致任务丢失，值班人员未仔细排查”的草稿。重写为事实、假设和未决证据；提出一个可验证的服务改进措施，以及一条有用户影响和延期风险依据的优先级理由。

**合同：**每项观察可追到来源/时区；未经证实的因果保留为假设；措施有 owner/截止/完成定义；语言讨论系统条件而非责怪个人。

**提示：**把定论拆成可观察证据与待验证因果，并明确如何知道措施降低了风险。
