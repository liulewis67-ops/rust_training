# M24-L02 三道短练习

## 预测：评审一份“能跑”的 API 说明

一份接口草稿只写了 `GET /reports`、返回 200 JSON，并给出含真实邮箱和 bearer token 的示例。预测一位非作者调用该接口会遇到的至少六个问题；覆盖授权/项目范围、查询约束/分页、失败语义、可重试边界、隐私和版本兼容。写出仍需产品或服务负责人确认的决策，不要自行补充业务承诺。

**合同：**缺口与实际调用或运行结果相关；将标准 HTTP 语义与本服务合同区分；无真实秘密或个人数据出现在替代示例中。

**提示：**调用者需要知道成功条件，也要知道权限失败、冲突、限流、依赖失败时的稳定行为。

## 修复：补全操作文档合同

starter 中的 `validate_operation` 接受缺少成功状态码或错误映射的文档。补齐验证，让空白操作 ID、方法、路径、认证说明、request ID header、成功状态码和错误代码分别返回稳定错误；保持合法文档通过。

**公开检查：**字段缺失/空白有测试，至少一个错误码须有效；校验失败不能自动生成响应或认证策略。

**提示：**先规定错误顺序，再用 `trim().is_empty()` 判断文本，数值状态码需处于 HTTP status code 的有效范围。
