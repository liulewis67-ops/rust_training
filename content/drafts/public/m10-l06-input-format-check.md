# M10-L06 独立检查：兼容新增日志输入格式

## 检查目标

旧版 `log-analyzer` 已被脚本和用户使用，输入格式为 `timestamp_ms|LEVEL|message`。现在需要支持一个只提供 tab 分隔导出的新数据源。请只根据本题和公开起始 ZIP 实现新增能力，同时保留旧格式的默认行为。不要查看教师参考、私有测试或其他答案。

## 输入契约

旧格式保持不变：

```text
10|ERROR|磁盘已满
```

新增格式为 `LEVEL<TAB>timestamp_ms<TAB>message`：

```text
ERROR<TAB>10<TAB>磁盘<TAB>已满
```

例如最后一行代表级别 ERROR、时间戳 10、消息 `磁盘<TAB>已满`。只有前两个 tab 是字段边界；消息可以为空、包含更多 tab 或 Unicode。完全空行跳过；缺字段、非法时间戳和未知级别使用已有结构化解析错误，并保留原始 1-based 行号。筛选和汇总共用现有语义。

## CLI 契约

- `--input-format pipe|tab` 选择输入语法，默认 `pipe`。
- 现有命令不加该参数时，行为与输出保持不变。
- `--input-format tab` 同时适用于 stdin 和 `--input PATH` 文件。
- 未知格式、缺值和重复参数属于使用错误：退出码 2、stdout 为空、stderr 有诊断。
- 两种格式共用过滤、text/JSON 输出和数据错误处理；`--format` 仍选择输出格式。

## 独立作答

先从 ZIP 解压到新目录，按 `starter-manifest.json` 检查每个文件哈希，运行 README 中的完整行为检查并记录旧、新契约的基线结果。实现后补充回归验证：

1. 旧 pipe 数据走默认参数仍通过；不得删除或削弱任何旧断言。
2. `fixtures/tab.log` 经 `--input-format tab` 汇总 3 条记录：ERROR=1、WARN=1、INFO=1。
3. 消息中的额外 tab 被保留；空行、错误类型和坏行号正确。
4. 新格式和旧格式通过同一过滤器与汇总逻辑。
5. fmt、workspace check/test、严格 Clippy 和 API 文档命令通过。

附一段说明，指出哪组旧测试证明兼容，哪组新测试证明能力扩展，以及为何不能通过删除旧功能来让新数据通过。公开检查对首个失败契约给出类别和期望/实际结果，允许查看反馈后重试。
