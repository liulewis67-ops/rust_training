# M24-L01 三道短练习

## 预测：找出含糊需求的决策缺口

产品方说：“项目经理可以快速下载所有相关任务。”列出至少五个会改变验收结果的未决问题，给出两个可能相反但都合理的例子，并把其中一个维度改写成可观察的 Given/When/Then。

**合同：**覆盖访问主体/项目归属、范围/时区、边界数据、可量化时延或错误行为、导出字段/隐私至少五类；区分事实、假设和待确认决策；示例 Then 必须描述外部结果而非内部方法。

**提示：**“快速”“所有”“相关”都需要边界；实现者不能自行决定权限范围或数据暴露。

## 修复：拒绝缺失的 Then

修复 starter 的 `validate_criterion`，在 requirement ID、scenario、Given、When、Then 与至少一个 `evidence_id` 任一缺失/空白时返回对应错误。维持合法条件通过，不得自动生成“通过”测试 ID。

**公开检查：**每种缺失字段有独立测试；合法 criterion 保持原样；空字符串与仅空白文本均视作缺失。

**提示：**`String::trim().is_empty()` 可统一识别空白文本。

## 实现：生成追踪行

实现 `build_trace_rows(criteria)`：先验证每项，再返回每条 criterion 的 requirement/scenario/evidence IDs；重复 requirement ID 需稳定拒绝；不得丢弃、合并或凭空创建链接。

**公开检查：**保持输入顺序和每条 evidence 顺序；空列表返回空行；重复 ID 和无效 criterion 都返回明确错误。

**提示：**先完整验证输入集合，再构建输出，避免返回部分成功的矩阵。
