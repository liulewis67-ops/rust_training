# M24-L02：设计说明、API 文档与运行手册

## 学完后

- 让设计决策、API 合同、业务验收与运行行为互相追踪。
- 写出调用者可执行的请求/响应示例、错误、认证、分页、限流和兼容约定。
- 为接手服务的值班人员提供无秘密依赖的启动、健康检查、排障、回滚和升级路线。

## 先写决策，再给实现者接口

设计说明回答为什么采用该边界、有哪些候选方案、约束和代价，以及哪些问题仍待决。用上下文图标明调用者、服务、持久化、外部依赖和信任边界；用序列图说明一次关键请求的授权、状态变化、重试与失败路径。只在决策影响安全、数据正确性、运维或成本时展开，不把整个代码目录抄进文档。

每个重要决策记录背景、决定、替代方案与后果，并关联 M24-L01 的 requirement/scenario IDs。明确不可接受的失败边界，例如跨项目读取、重复请求造成重复副作用、未经授权的数据进入日志。未定结论写为 open question，标明负责决策的人和影响面；不要把临时猜测写成稳定事实。

## API 文档必须能指导调用

OpenAPI 是与语言无关的 HTTP API 描述格式，可让人和工具发现接口，而无需查看服务源代码。[OpenAPI Specification](https://spec.openapis.org/oas/v3.1.2.html) 但格式有效不等于合同完整：每个操作还要解释用途、授权、路径/query/header/body 字段、约束、成功响应、可预期错误、分页/排序、限流、幂等与兼容策略。请求和响应示例必须与 schema 一致，示例中的 token、邮箱、项目 ID 应为合成值。

```http
GET /v1/projects/prj_demo/tasks?from=2026-01-01&to=2026-02-01&limit=50
Authorization: Bearer <access-token>
X-Request-Id: req_demo_01
```

```http
HTTP/1.1 200 OK
Content-Type: application/json
X-Request-Id: req_demo_01

{"items":[],"next_cursor":null}
```

示例只能表达已确认的业务语义。课程例子使用 UTC 日期范围，但产品若采用本地时区或闭区间，应在业务契约、schema 描述和测试中一致地写出。列清 401/403/404/409/422/429/5xx 等适用边界和稳定错误码，说明哪些错误安全可重试、何时退避、幂等键在何范围有效。HTTP 状态码和方法语义应遵循 HTTP 规范并说明本 API 的具体行为；不能只复制标准术语。[RFC 9110](https://datatracker.ietf.org/doc/html/rfc9110)

## 运行手册服务于非作者

Runbook 要让具有合适权限的服务接手人完成明确任务。开头列出适用服务/版本、影响、所需角色和安全前置；给出可复制的无秘密配置模板、启动与健康检查、常见告警诊断、只读验证、缓解/回滚、停止操作、升级联系和预期时长。每条命令说明在哪个环境执行、成功观察是什么、失败时下一步是什么。命令中的密钥仅用环境变量名称占位，不给真实值，也不要求读者临时去作者机器取文件。

操作步骤应先保护数据和用户，再采取可逆缓解。恢复、迁移、权限变更和删除等高影响操作须列出前置检查、影响范围、幂等性、停止条件和回滚限制；不确定时停止并升级，而不是让操作者猜。健康检查说明 readiness 和 liveness 的不同目的；日志/指标查询示例应限制字段，避免复制个人资料或秘密。架构决策记录 why，API reference 说明 what/how，runbook 指导 what to do when；三者相互链接，各自维护。

## 可维护性与变更

文档与代码一同评审。针对 breaking change 更新版本兼容说明、迁移窗口、弃用期限和消费者动作；对行为变化同步更新验收场景、API schema、示例、错误目录和 runbook。生成的 OpenAPI 不应成为无法追踪的副本；注明单一事实来源并在 CI 检查 schema/示例至少可解析。检查中的契约通过，也不代表真实部署或权限已验证。

## 分层提示

1. 哪个决策改变了数据模型、权限或失败行为？文档如何链接到对应需求和验收场景？
2. 客户端收到 409 与 503 时分别能否重试？还需要哪些幂等和 Retry-After 约定？
3. API 示例中的空结果、跨项目访问、分页和日期范围各自会返回什么？业务尚未确认的部分如何标记？
4. 值班人员如何判断变更安全、健康检查失败和依赖不可用？哪些操作必须停止并升级？
5. 如果授权 scope 扩大或响应增加个人字段，哪些 API 文档、测试、日志审查和版本说明需要一起更新？
6. 新同事只有仓库和只读观测权限，没有作者个人环境秘密，能否从文档启动测试实例？缺什么就记为文档缺口。
