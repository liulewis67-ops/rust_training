# M24-L06 独立检查：陌生增量需求、排障与项目答辩

这是一次独立检查。Evaluator 会在 ready 后分配陌生业务变式和故障证据；本页不展示变式、故障注入细节、评分答案或参考补丁。

## 你需要提交

1. 对陌生需求补齐需求/场景、可观察验收、权限和边界决策；未确认的产品规则要标为 open question。
2. 提交实现 revision、针对增量需求的回归测试、API/设计说明和必要的兼容/变更记录。
3. 用提供的日志、指标、时间线和变更快照诊断故障；把事实、假设、待验证证据和安全缓解分开。
4. 给出 P4.1–P4.5 交付 manifest：build/provenance、运维、应用回滚与数据恢复、固定 workload 性能与正确性、维护交付。没有执行的步骤写 `not_run`，不要伪造通过。
5. 答辩取舍、用户影响、剩余风险、验证边界和回滚条件；说明如何干净重置练习环境。

## 通过原则

- 先满足功能、安全和数据正确性合同，之后再解释性能主张。
- 不将 hash/计划/截图当作真实环境行为证据；性能需同环境/负载重复样本、原始报告、profile 和不确定性分析。
- 解释要对应提交与证据 ID。无证据支持的因果保持为假设。
- 只有授权评审通过全部硬门槛、首次独立提交、未查看答案且 cleanup 成功，才可能生成课程技能证据。
- Evaluator/runner 故障返回 `platform_error`，不判学习者失败，不降低已有能力状态；平台恢复后可按规则重试。

这次检查衡量课程目标，不代表真实生产服务已完成部署或恢复。请等待 evaluator 明确 ready 再开始计时或提交。
