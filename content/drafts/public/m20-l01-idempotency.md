# M20-L01：幂等键和重复请求

- 说明唯一约束和事务如何阻止并发重复创建，以及幂等记录的过期策略会改变什么。

## 先修

完成 M19-L06，理解授权需针对每次请求重新检查；理解 HTTP 请求、JSON 输入和数据库事务的基本概念。M20-L01 聚焦一次创建操作：一次 POST 超时后，客户端不知道服务端是否已经提交，因此用相同键安全重试。幂等是“业务效果只发生一次”，不是“网络只投递一次”。

## 请求键、操作和请求指纹

客户端为一次逻辑操作生成唯一键，并在超时重试时保留该键。服务端查找的不是单独一个全局字符串，而是一个明确的幂等作用域，例如 `(authenticated_user_id, operation, key)`。因此两个用户可以使用同样的键；一个用户在创建任务和创建项目等不同操作中也可以分别使用相同键。

服务端还需要识别请求是否相同。对创建任务而言，指纹至少要绑定操作、项目和规范化后的标题。相同作用域、相同指纹表示重试，可返回第一次保存的任务和结果；相同作用域、不同指纹表示键被错误复用，应返回稳定冲突错误（本课约定 409 `idempotency_conflict`），且不得创建或改写任务。

示例契约（头部值的具体语法属于本 API 自己公开的约定）：

```http
POST /api/v1/projects/project-7/tasks
Idempotency-Key: retry-8f2
Content-Type: application/json

{"title":"准备发布"}
```

成功首请求创建一个任务并保存可重放结果；重复请求返回相同任务，不再新增业务对象。同键不同标题或项目则冲突。不能因为第二次请求返回 200 就推断其一定安全；应同时检查任务数量、返回的 task ID 与第一次请求一致。

## 并发与原子性

单进程 `HashMap` 或 `Mutex` 能帮助学习查找和重复判断，但多个服务实例、进程崩溃和持久化都不在其保证范围内。生产实现需要数据库唯一约束把幂等作用域作为原子争用点，并在一个事务中完成：权限检查、幂等记录保留、业务对象插入和保存 replay target。任一步骤失败时整体回滚，避免“任务已写入但幂等结果未保存”的半完成状态。

并发的两个相同请求可能同时查不到已有记录。先查再插入若没有唯一约束，仍可能双写。唯一约束/唯一索引和事务负责串行化冲突；捕获冲突后重新读取已提交记录，比较指纹，再选择重放或 409。重放之前仍要按当前身份重新验证项目权限，不能让旧记录绕过现有授权。

幂等记录需要公开保留期和过期行为。过期后相同 key 可能再次执行并产生新对象，所以客户端不得把过期键当作永久去重标识。保留期限、正在处理中的并发请求语义及失败结果是否缓存，必须由服务端契约写明。本练习固定采用：创建成功后 24 小时内可重放；相同 key 不同指纹冲突；认证/授权与输入错误不缓存为成功结果。

## 分层提示

1. **超时提示**：客户端不知道请求有没有提交时，换新 key 会造成什么风险？
2. **作用域提示**：全局 key 会不会误伤另一个用户？同一个 key 在“创建任务”和“创建项目”中表示同一操作吗？
3. **指纹提示**：为什么 key 相同但标题不同不能简单返回旧任务？哪些字段必须属于规范化指纹？
4. **竞态提示**：两请求同时读到“key 不存在”后，什么数据库约束是最终裁判？
5. **事务提示**：任务写入成功、结果记录失败会导致什么？哪几步必须原子提交？
6. **授权提示**：旧 key 命中重放记录时，是否还需要验证当前用户对项目的访问权？
7. **保留期提示**：若键 24 小时后可再次执行，客户端该如何理解重试安全边界？

## 来源

- [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)：HTTP 方法幂等语义；不能把应用层带键的 POST 误称为 HTTP 方法本身幂等。
- [PostgreSQL 约束](https://www.postgresql.org/docs/current/ddl-constraints.html) 与 [INSERT / ON CONFLICT](https://www.postgresql.org/docs/current/sql-insert.html)：数据库唯一性约束与并发冲突处理机制。
- [IETF Idempotency-Key Internet-Draft 历史](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/history/)：参考其键唯一性、请求指纹和重放概念；该版本已于 2026-04-18 过期，不是 RFC 标准，API 必须自己公开兼容契约。

题目中的路由、作用域、错误码和 24 小时保留期是原创教学 API 合同。作者侧练习不替代 R3/PostgreSQL 并发及故障验收。
