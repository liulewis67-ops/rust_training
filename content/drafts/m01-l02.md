# M01-L02：rustup、Cargo、Edition 与项目结构

## 先修与环境基准

先修 M01-L01，并能在终端进入项目目录、运行一条命令和查看文本文件。

## 学习目标

读完本节后，你可以区分 Rust 工具链、编译器、包管理与 Edition，并从一个 Cargo 项目中找到入口源码、项目清单和锁文件。

## 先认清工具各自负责什么

安装 Rust 时通常会一起使用 `rustup` 和 Cargo。`rustup` 管理工具链及其组件；`rustc` 编译 Rust 源码；Cargo 管理项目、依赖和常见开发命令。它们有关联，却不是同一个程序。遇到“版本不对”“缺 formatter”或“依赖解析失败”，先辨认是哪一层负责，再选择检查入口。

团队协作时需要知道当前目录实际使用哪个工具链。个人默认工具链方便日常开发；仓库可以用 `rust-toolchain.toml` 声明团队要用的渠道、组件或目标平台。进入项目后查看 `rustup show`，再对照仓库配置，可以解释为什么两台机器执行同一条 `cargo` 命令却得到不同版本或缺少工具。

## Edition 是 crate 的语言约定

Rust Edition 让语言逐步演进时保留旧项目的兼容路径。一个 crate 在 `Cargo.toml` 的 `[package]` 区域写 `edition`，说明它采用哪一版语法与迁移规则。Edition 不是 rustc 的版本号，也不是 Cargo package 的版本号。编译器升级和 crate 迁移是相关但不同的决定。

不同 Edition 的 crate 可以在同一依赖图中互相使用。团队因此可以按 crate 逐步迁移，而不必一次改完整个依赖生态。选择 Edition 时应考虑项目的工具链基线、依赖和迁移目标；不要只看年份数字就推断语言功能支持或运行性能。

## Cargo 项目的几个关键文件

通过 Cargo 建立的最小应用通常包含 `Cargo.toml` 和 `src/main.rs`。清单写项目元信息、Edition、依赖和构建设置；`src/main.rs` 是二进制程序常见入口。库 crate 常用 `src/lib.rs`。更大的项目还可能拆成多个 package 和 workspace member。

`Cargo.lock` 记录依赖解析的具体结果。应用程序通常提交它，方便不同开发者和自动构建使用一致的依赖版本；库项目是否提交需遵守仓库约定。锁文件不会替代 `Cargo.toml`：前者记录一次解析结果，后者表达项目声明的依赖条件。

仓库导航时先找 `Cargo.toml`。如果它定义 `[workspace]`，再看 `members` 或 workspace 默认成员；不要假设每个文件夹都是独立项目。理解清单和目录之后，再跑命令，就更容易判断 Cargo 正在操作哪个 package。

## 建立一个可重复的第一步

安装完成后，先查询工具链，再用 Cargo 创建一个小应用。检查生成的清单和入口源码，确认项目选择的 Edition 与课程环境一致。接下来可以编译并运行默认程序；本节关注工具之间的分工，如何用不同命令定位构建问题会在下一节练习。

如果命令无法识别，检查安装是否完成以及终端是否刷新 PATH；如果提示 toolchain 或组件缺失，查看仓库配置并让 rustup 安装匹配项；如果 Cargo 在别的目录找到项目，回到包含目标 `Cargo.toml` 的目录重试。不要先删锁文件或升级整套依赖，因为这些动作会改变问题现场。

### 正常路径示例

在一个尚不存在的练习目录旁运行：

```powershell
cargo new hello-rust
Set-Location hello-rust
rustc --version
cargo --version
Get-Content Cargo.toml
cargo run
```

检查清单中的 `[package]`、`edition` 与 `src/main.rs`，再观察 Cargo 构建并启动新程序。默认应用应打印 `Hello, world!`；运行后也可查看 Cargo 生成或维护的 `Cargo.lock`。

### 失败示例：在错误目录运行 Cargo

如果终端当前目录不在 `hello-rust` 项目内，直接运行 `cargo run`，Cargo 会报告找不到项目清单。先用 `Get-Location` 查看当前路径，再 `Set-Location hello-rust`，确认该目录里存在 `Cargo.toml` 后重试。具体诊断文本可能随 Cargo 版本变化；排错依据是当前目录和项目清单的位置，而不是照抄某段错误文案。

另一个常见误判是把 `edition` 当作 rustc 版本：把 crate 的 Edition 改掉不会安装或切换编译器。先分别查看 `rustc --version`、仓库的 `rust-toolchain.toml` 和 `Cargo.toml`，再决定需要修正工具链还是 crate 清单。

## 本节小结

- `rustup` 选择和管理工具链，`rustc` 编译代码，Cargo 管项目和开发流程。
- `edition` 属于 crate 的语言约定；工具链版本、crate/package 版本和 Edition 不是同一概念。
- `Cargo.toml` 表达项目声明，`Cargo.lock` 固定一次依赖解析结果。
- 从 `Cargo.toml` 开始认识项目结构，再运行命令并记录所用工具链。
