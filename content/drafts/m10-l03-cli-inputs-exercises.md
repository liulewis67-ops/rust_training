# M10-L03 短练习：CLI 输入与输出边界

## 1. 预测：哪个输入获胜？

规则是 CLI 参数 > 配置文件 > 环境变量 > stdin。依次预测输出来源或失败类别：

1. --name cli、有效配置值 file、环境值 env，stdin 为 pipe；
2. 未提供 --name，配置文件路径不存在，环境值与 stdin 都有内容；
3. 所有高优先级来源缺省，PROFILE_NAME 未设置，stdin 为 pipe；
4. --name 空字符串，其余来源都有合法值。

同时指出 stdout、stderr 和退出码的预期。

**分层提示**

1. 按顺序看每一项来源是否存在。
2. 显式指定的配置文件必须读取成功，优先级较低不代表可以忽略配置错误。
3. 空字符串仍是已提供的值，领域校验不会回退到下一来源。

## 2. 修复：不要吞掉配置文件错误

现有实现用 fs::read_to_string(path).ok().and_then(parse_config)；配置文件打不开时它继续从环境或 stdin 取值，返回成功结果。修复错误传播，满足以下契约：

- 显式给出 --config PATH，读取或语法错误就退出 2；
- stdout 为空，诊断写 stderr；
- 没有给出 --config 时才考虑环境变量或 stdin。

指出是哪一个 Result 被悄悄丢弃，并说明参数名优先时为何仍检查显式配置路径。

**分层提示**

1. 将“没有配置文件参数”与“配置文件读取失败”区分开。
2. 通过 map_err 或问号运算符保留失败类别。
3. 在真实二进制测试 status、stdout、stderr。

## 3. 测试补全：验证来源优先级和错误流

补全子进程测试，使它验证至少以下案例：

- CLI 参数胜过合法配置、环境和 stdin；
- 配置胜过环境和 stdin；
- 环境胜过 stdin；
- 全部缺省时读取 stdin，且管道关闭后退出；
- 不存在的配置文件导致非零约定退出码、stderr 有诊断且 stdout 为空。

给出每个案例需要设置的参数/环境/管道内容及预期输出。测试需要启动 CARGO_BIN_EXE_profile-cli。

**分层提示**

1. 先清除继承的 PROFILE_NAME，再只设置当前案例所需值。
2. 用 Command 配 stdin 管道并写入后关闭，避免子进程等不到 EOF。
3. 检查 status.success()、stdout 与 stderr，不能只断言一个领域函数的返回值。
