# M01-L05：实验——让一个失败项目重新通过

下载[实验起始项目 ZIP](./public/m01-l05-starter.zip)。项目中有一个类型错误；修复后，公开测试还会暴露一个折扣比例逻辑错误。保留题目契约和测试，记录每次失败、修改和复验结果。

## 目标与准备

本实验练习一条完整的修复循环：打开一个已有 Cargo 项目，识别它失败在编译还是行为检查，修复根因，重跑相关检查，再确认差异可以复查。开始前应知道 Cargo 项目的基本文件，并能按 M01-L03/L04 选择命令和查看 Git 状态。

## 场景

你接手一个小型终端工具的练习仓库。上一位维护者留下了两个问题：一个会让构建失败，另一个会让正常输入得到错误结果。项目已经带有公开测试，任务是让原有契约重新通过，而不是删掉失败测试或放宽题目要求。

起始项目使用整数分计算折扣。实验开始时记录工具链版本、分支和工作区状态；结束时应能从全新的起始项目再次完成修复。

## 任务步骤

1. 阅读仓库说明，并记录当前工具链、分支和工作区状态。
2. 先运行快速编译检查，保存首次失败信息；从诊断确定构建失败位置。
3. 修复编译问题，再运行公开测试，按预期值和实际值找出行为错误。
4. 修改实现，不删除或削弱公开测试；重新运行对应检查并确认整个实验通过。
5. 查看最终差异，说明每项修改对应哪个失败证据，并提交修复。
6. 重置实验，再按记录从初始状态走一遍，确认步骤可以重复。

## 验收契约

- 正常版本必须从干净工作区稳定复现至少一个编译失败和一个行为测试失败。
- 参考修复必须解决根因；错误变体必须仍被公开检查检出。
- 删除或弱化断言不能得到有效验收结果；题目检查需对测试改动有明确检测办法。
- 恢复操作会清除学员改动并回到版本化起点，重置前提供保存工作提醒。
- 实验结束时能展示原始失败、修复后的检查结果和对应差异。

## 评测与工作区恢复

本地测试用于帮助定位问题。正式验收还会核对起始快照和公开测试是否被改动，并通过独立行为用例检查修复结果；只修改公开断言、删除测试或展示本机输出不能作为通过证据。重置前先另存需要保留的工作，随后从干净起始项目重新开始。

## 分层提示

1. 先辨认失败命令和阶段。
2. 对照失败行附近的类型与函数契约。
3. 比较测试断言、输入和实现的边界处理。
4. 查看参考修复并解释为什么删测试不是修复。
