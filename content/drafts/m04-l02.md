# M04-L02：`move` 的发生位置

## 学完后

- 在赋值语句中标出 `String` 所有权从旧绑定转到新绑定的位置。
- 识别值传递给按值参数时发生的 move，并解释函数返回后原绑定不可再用。
- 跟踪函数返回值把所有权转给调用方的方向。
- 阅读 E0382，定位移动表达式与之后仍尝试使用旧绑定的位置。

## 先修

完成 M04-L01，能定位 owner 的作用域边界，并根据输出判断值何时被销毁。本节只跟踪 `String` 在赋值、按值参数和返回表达式处的所有权转移；不借用、不克隆，也不讨论字段部分移动。

## 赋值：从源绑定移到新绑定

`String` 拥有堆上缓冲区。把它赋给另一个变量时，所有权从旧绑定移到新绑定；不会把同一缓冲区复制成两个独立 owner：

```rust
/// Transfers a string to a new binding.
fn main() {
    let first = String::from("map");
    let second = first;
    println!("{second}");
}
```

输出为 `map`。移动发生在 `let second = first`：`second` 成为值的新 owner。若下一行改成 `println!("{first}")`，程序会因 E0382 拒绝编译，因为 `first` 已不再拥有可用的 `String`。

```rust
/// Tries to use the source binding after moving its String.
fn main() {
    let first = String::from("map");
    let second = first;
    println!("{first}");
    println!("{second}");
}
```

这个反例在打印 `first` 的位置触发 E0382；正确示例只读取 owner `second`。

```text
before assignment:
binding `first` ──owns──> String value ──owns──> heap buffer "map"

after `let second = first`:
binding `first`   (moved-from; cannot use the String)
binding `second` ──owns──> same String value ──owns──> same heap buffer "map"
```

这是所有权关系示意，不代表每个绑定或值固定放在物理内存的某个地址。赋值后只有 `second` 可以用这个值；离开作用域时由当前 owner 负责清理。

## 按值参数：调用把 owner 交给函数

参数类型写 `String` 而不是引用时，调用者把所有权交给函数。函数使用参数并返回后，参数 binding 结束；调用处原来的名字也已经移动：

```rust
/// Prints a label after taking ownership of it.
fn print_label(label: String) {
    println!("label: {label}");
}

/// Transfers the label to the function.
fn main() {
    let task = String::from("review");
    print_label(task);
}
```

输出是 `label: review`。move 发生在调用表达式 `print_label(task)`，参数 `label` 接过 owner。若调用后再打印 `task`，则会得到 E0382。函数按值接收并使用后没有把值返回，因此调用处不能继续用原绑定。

```rust
/// Takes ownership of the label and prints it.
fn print_label(label: String) {
    println!("label: {label}");
}

/// Tries to reuse the caller binding after a by-value call.
fn main() {
    let task = String::from("review");
    print_label(task);
    println!("after call: {task}");
}
```

反例的 E0382 位于调用后读取 `task` 的位置；按值参数没有将 owner 自动交还。

## 返回表达式：把 owner 交回或交给调用方

函数可以返回它收到的 owned value；返回表达式把所有权转给调用方的目标绑定：

```rust
/// Prints a label and returns its ownership to the caller.
fn announce_and_return(label: String) -> String {
    println!("label: {label}");
    label
}

/// Receives the returned owner under a new binding.
fn main() {
    let task = String::from("review");
    let task = announce_and_return(task);
    println!("available: {task}");
}
```

输出为 `label: review`，然后是 `available: review`。调用参数先将 owner 移入参数 `label`；最后的 `label` 尾表达式再将 owner 移回调用点，外层新绑定 `task` 接管返回值。第一个 `task` 在调用处已经移动，第二个同名绑定取得返回值；此处 shadowing 不会复制出第二个 owner。

```rust
/// Moves a local String into a return binding.
fn make_label() -> String {
    let local = String::from("review");
    let returned = local;
    println!("still local: {local}");
    returned
}

/// Tries to use a value after moving it toward the return expression.
fn main() {
    println!("{}", make_label());
}
```

这里在打印 `local` 时触发 E0382：`returned` 已接过 owner，稍后从函数返回的也是 `returned`。正确返回版直接以当前 owner 作为尾表达式，不在移动后再读取旧绑定。

## 读 E0382：找出移动点和旧绑定使用点

看到 `use of moved value` 时，先从诊断行反向追踪该值最近一次赋值、按值实参或返回位置。再找旧绑定被再次读取的位置；错误的关键不是名字仍存在于文本中，而是该绑定已不再持有这个值。修复时要明确选择所有权应该留在哪一侧：让旧值不再使用、返回所有权，或调整 API 接收方式。借用与复制策略将在后续单元展开，本节不把它们当默认补丁。

## 检查顺序

1. 写出每个 owned `String` 当前对应的 owner。
2. 标出赋值、按值函数实参和函数返回表达式的转移方向。
3. 检查转移后旧绑定是否仍被读取；若是，定位 E0382 的源语句与使用语句。
4. 对修复版重新画 owner 图并运行程序，确认输出来源于当前有效 owner。
