# M12-L05 实验：并行日志统计

## 实验目标

实现一份可与串行基线核对的并行日志统计程序。完成后应能：

- 解析带行号的日志输入，跳过完全空行并对非法记录返回错误；
- 将输入按稳定分块分配给多个 worker，统计总记录、级别计数、消息字节数和时间范围；
- 收集并 join 每个 worker，报告最早输入位置的解析错误或 worker panic；
- 保证失败时不返回部分统计结果；
- 从公开 ZIP 干净重置，复现预期失败、修复及全套本地检查。

这是 M12 的综合实验，不新增或重复计算短练习。公开起始包故意忽略 worker 的错误结果，因此能编译，且除一条错误传播契约外的基线测试应通过。教师参考实现保留在私有目录，不要复制到公开起始包。

## 项目契约

输入每条非空记录采用 `timestamp_ms|LEVEL|message`，时间戳为 u64，LEVEL 为 ERROR/WARN/INFO/DEBUG；message 可空、可含额外竖线或 Unicode。行号从 1 开始，空行仍占行号。串行实现是行为基线；对有效数据，任意 worker 数（含 0，按 1 个 worker 处理）的并行统计必须逐字段相等。

解析错误必须保留最早的输入行号和错误类别。所有 worker 必须 join，即使其中一个返回错误；若 worker panic，应明确转成错误。失败时整体返回 Err，不可把成功 worker 的部分和当作完整结果。空输入返回零统计。示例使用 checked arithmetic 检出计数溢出。

每 worker 的局部统计只包含固定数量字段；最终内存开销取决于输入文本、worker 数和固定大小统计，不应创建与记录总数等大的重复结果数组。起始模板可存储输入行；R2 的峰值内存门槛须由平台固定工作负载与受控测量确认，本地小样本不替代它。

## 实验阶段

### P1.1 解析与串行基线

核对 u64 时间戳、四种级别、空 message、message 内竖线、Unicode、空行、缺字段、时间戳错误和未知级别。错误要含 1-based 行号。串行 `serial_stats` 定义正确输出。

### P1.2 并行分块

把输入切成至多 worker_count 个近似等长连续分块。每个 worker 独立产生局部统计；父线程 join 所有 worker 并合并成功结果。解析错误按输入行号稳定选择，不能按 worker 完成先后选择。

### P1.3 错误传播和等价性

有效公开输入在 1、2、3、超过输入行数和 0 worker 配置下都要与串行结果一致。含无效行时并行计算必须返回与串行相同的错误，且不能暴露 partial stats。至少补一条回归测试，修复起始模板静默忽略错误的行为。

### P1.4 可复现与受控验收

保留 README、公开 fixture、预期结果、Cargo.lock、重置说明及 starter-manifest.json。清洁解压后核验 manifest，并用 locked/offline 执行 fmt/check/test/严格 Clippy/doc。记录 ZIP 与清单 SHA-256。

R2 并发资源验收须使用固定大数据集、固定工具链、隔离 worker 限额和内存预算；记录吞吐、耗时、峰值内存、worker 数与评测器版本。没有 R2 数据时只报告作者侧行为验证，不推断资源达标。

## 工作步骤

1. 将公开 ZIP 解压到新的、唯一的起始目录；先核验 manifest 并保留不可修改的起始快照。
2. 运行 fmt/check/test，确认基线可编译；预期仅错误 worker 未被传播的行为断言失败。
3. 先完善串行解析基线，再实现稳定分块、join 全部 worker、择取最早输入错误和不返回 partial stats。
4. 对有效输入将 serial 与 parallel 结果做结构相等断言；对错误输入比较错误行号和类别。
5. 运行全部本地检查，在另一目录从同一原始 ZIP 重置并复现基线。
6. 平台可用时，才在 R2 测量数据规模和峰值资源；平台不可用或 I01-F06 暂缓时记录为未验收。

## 重置与证据

重置只能从公开 ZIP 再解压到新目录，不要从修复副本反向覆盖起始快照。保存 ZIP SHA-256、manifest 各文件哈希、题目版本、工具链、测试输出、错误变体反馈、工作区快照/版本、评测器版本、受控输入数据哈希和资源测量。平台提交快照、隔离运行及独立学习者试做仍需正式 R2 服务；作者侧 ZIP 检查不代表这些门槛通过。
