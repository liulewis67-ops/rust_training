# M10-L06 独立检查：兼容新增日志输入格式

> **综合自测：** 为已交付的 CLI 添加 tab 输入格式，如何在共享解析逻辑的同时保持旧 pipe 行为完全兼容？

## 学习目标与先修

完成 M10-L01–L05，已经具备一个自己创建并通过基本测试的 `log-core` / `log-cli` 工程。M10 的 P1 起始包尚未完成验证；本节仍为**预发布草稿**，不提供托管评测或可下载的正式 ZIP。

## 场景：已有用户依赖默认日志格式

脚本和监控系统仍然向日志工具传输 `timestamp_ms|LEVEL|message`。新增导出源改用 tab，并且消息里允许出现额外 tab。修改时最重要的是旧命令无需更改就能继续工作。

**先预测：** `ERROR<TAB>10<TAB>磁盘<TAB>已满` 应该被拆成几个字段？旧版没有 `--input-format` 的调用是否应该自动猜测新格式？

## 检查目标

旧版 `log-analyzer` 已被脚本和用户使用，输入格式为 `timestamp_ms|LEVEL|message`。现在需要支持一个只提供 tab 分隔导出的新数据源。请根据本题与 M10-L05 的自建 Cargo 工程实现新增能力，同时保留旧格式的默认行为；先独立预测，再编写和运行回归测试。

## 输入契约

旧格式保持不变：

```text
10|ERROR|磁盘已满
```

新增格式为 `LEVEL<TAB>timestamp_ms<TAB>message`：

```text
ERROR<TAB>10<TAB>磁盘<TAB>已满
```

例如最后一行代表级别 ERROR、时间戳 10、消息 `磁盘<TAB>已满`。只有前两个 tab 是字段边界；消息可以为空、包含更多 tab 或 Unicode。完全空行跳过；缺字段、非法时间戳和未知级别使用已有结构化解析错误，并保留原始 1-based 行号。筛选和汇总共用现有语义。

## CLI 契约

- `--input-format pipe|tab` 选择输入语法，默认 `pipe`。
- 现有命令不加该参数时，行为与输出保持不变。
- `--input-format tab` 同时适用于 stdin 和 `--input PATH` 文件。
- 未知格式、缺值和重复参数属于使用错误：退出码 2、stdout 为空、stderr 有诊断。
- 两种格式共用过滤、text/JSON 输出和数据错误处理；`--format` 仍选择输出格式。

## 分阶段验收

| 阶段 | 应验证的结果 |
| --- | --- |
| ① 兼容性 | 默认 pipe 行为及旧测试原样通过，输出不变 |
| ② 新格式 | 新增 tab 输入支持文件和 stdin；只拆前两个 tab |
| ③ 输入失败 | 未知格式、缺参数值、重复选项返回退出码 2 |
| ④ 解析边界 | Unicode、空消息、重复 tab、错误行号均正确 |
| ⑤ 完整交付 | fmt、check/test、严格 Clippy、文档与 README 同步 |

**与 Java/Go 对比：** 与向 Java/Go CLI 新增输入适配器类似，Rust 的主要设计目标是解析层依赖输入格式策略，而过滤和统计仍共享领域逻辑。不要为了新格式在 CLI 中复制一套统计函数。

## 独立作答

从上一阶段未修改的 Git commit 建立一个新工作分支，记录旧格式的实际测试结果，然后实现并增加以下回归：

1. 旧 pipe 数据走默认参数仍通过；不得删除或削弱旧断言。
2. 自制 `fixtures/tab.log` 以 tab 模式汇总 3 条记录：ERROR=1、WARN=1、INFO=1。
3. 消息中的额外 tab 被保留；空行、错误类型和坏行号正确。
4. 新格式和旧格式共用原有过滤器、text/JSON 渲染及统计逻辑。
5. 格式、workspace check/test、严格 Clippy 和 API 文档命令通过。

提交一段说明，列出原有测试如何证明兼容、新测试如何证明扩展，并指出为何删掉旧功能不符合契约。测试失败时记录实际结果、期望结果和修复步骤，不把编译错误当成业务通过证据。

## 自查清单

- [ ] 无 `--input-format` 时完全保持 pipe 格式，不做隐式探测。
- [ ] tab 模式只消费前两个 tab，消息保留后续 tab 与 Unicode。
- [ ] 缺失、未知、重复的 CLI 选项都按使用错误处理。
- [ ] 新旧格式走同一过滤/汇总路径，新增回归不削弱旧断言。
- [ ] 有真实命令、退出码与测试结果可供复验。
