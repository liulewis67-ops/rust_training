## 实验目标

为一个小型服务配置编写严格解析器，在拒绝错误配置时指出字段和准确位置。完成后能解释：

- 为什么错误类型应保留类别、字段和位置，而不保存或回显原始配置值；
- 如何处理空值、格式错误、缺失字段和重复字段；
- 行号与列号从哪里计数，以及 Unicode 列号为什么不能直接使用 UTF-8 字节偏移；
- 如何通过行为测试区分解析失败与编译失败。

## 输入与输出契约

输入是 `key=value` 行组成的 UTF-8 文本，字段可按任意顺序出现，空行忽略。只接受下面两个必填字段，且每个必须恰好出现一次：

| 字段 | 类型 | 示例 |
|---|---|---|
| `timeout_ms` | `u64` 十进制数字 | `timeout_ms=250` |
| `retry_limit` | `u8` 十进制数字 | `retry_limit=3` |

不允许空格、注释、未知字段或重复字段。数字值只能包含 ASCII `0`–`9`，空值、非数字和类型范围溢出都作为该字段的 `InvalidValue`。输入可使用 LF 或 CRLF 行结束符。

解析成功返回 `Config { timeout_ms, retry_limit }`。失败返回 `ConfigError`，不应将配置原文或非法值放进错误：

- 行号从 1 开始；列号从 1 开始，按 Unicode scalar value（Rust `char`）计数，不按 UTF-8 字节计数。
- 缺少 `=` 时，位置是该行末尾之后、预期 `=` 所在的列。
- 未知字段与重复字段指向字段名的首列；重复错误还指出字段名。
- 无效值指向 `=` 后第一个值字符的位置；空值指向值本应开始的位置。
- 缺失字段指向输入结束处的下一行第 1 列，同时包含缺少的字段名。空输入缺失位置为第 1 行第 1 列。

## 先预测：Unicode 会怎样改变错误列号

给定 `"变更timeout_ms"` 这行不带等号的非法文本，UTF-8 字节长度与 Rust `chars().count()` 不相同。按本题规则，报错列号应是**字符数量 + 1**，不是字节数量 + 1。

**先预测：** `"retry_limit=256"` 是解析失败还是有效配置？`"timeout_ms=20\ntimeout_ms=30"` 应返回什么错误？如果 `timeout_ms` 和 `retry_limit` 均缺失，错误应在什么位置出现？

## 原理推导与反例辨析：交付严格配置解析

**问题：** 配置重复键与 UTF-8 字符列会破坏错误准确性。

**原理与推导：** 严格配置解析器的错误位置不仅是字节下标，还需按课程约定定义行列单位；重复字段也必须有确定的拒绝或覆盖策略。

**示例与证据：** 对照本节原有代码或实验核验：L05 起始失败测试转绿且不回显输入。

**反例：** 对 UTF-8 文本把字符列与字节列混用，会给错误提示一个错误位置；默默覆盖重复键可能掩盖重要配置错误。

**独立练习：** 构造重复键、非法数字、Unicode 前缀和空输入，逐项断言 ConfigError 的类别、位置与来源。

**复盘：** 复盘解释为何位置和分类是稳定 API 契约的一部分，而非可随意变动的错误字符串。

## 进阶边界：真实公开测试

新增真实工程边界测试：`u64::MAX` 与 `u8::MAX` 必须正确解析，溢出和多字节无 `=` 输入返回稳定类别与**字符列**；如果第三行重复字段、第四行未知字段，先报告第三行的重复错误；同一重复字段的第二个值即使是 `999` 也应报告 `DuplicateField`，而不是覆盖后报告越界。参考工程现在需通过 **11 项公开测试**；起始工程保留 **4 项故意失败**。

## 分阶段验收

| 阶段 | 证据 |
| --- | --- |
| ① 字段结构 | 只接收两种必填字段，空行可跳过 |
| ② 失败类别 | 空值、非数字、越界、重复键、未知键分别报错 |
| ③ 精确位置 | LF/CRLF、Unicode、缺少 `=` 与 EOF 位置正确 |
| ④ 安全输出 | 结构化错误包含字段与位置，但不回显非法值 |
| ⑤ 可重复验证 | 本地测试包含正常和失败断言，记录 Rust 版本与测试命令 |

**与 Java/Go 对比：** Rust 的 `str::len()` 与 Go `len(string)` 一样统计 UTF-8 字节数，而 Java `String.length()` 统计 UTF-16 代码单元。用户可见列号必须先定义单位；这里使用 Rust `char` 计数，不等于任意语言的默认字符串索引。

## 分层提示

1. **解析结构**：先枚举 `str::lines()` 的行，再以 `split_once('=')` 定位键和值；将 0-based 行序号转为面向用户的 1-based 行号。
2. **数值与上下文**：`parse::<u64>()` / `parse::<u8>()` 给出范围检查；把底层错误转为稳定的字段错误，不保存非法值。
3. **列位置**：`str::len()` 返回字节数；面向本契约的字符列应按 `chars().count()` 计算。
4. **重复项**：`Option` 中已有值说明必填字段已出现；在写入新值前返回 `DuplicateField`。
5. **缺失字段**：解析完毕后检查两个必填项；EOF 的行号是最后一行之后的下一行，空输入从第 1 行开始。

## 自查清单

- [ ] 非 ASCII 字符的列位置按 `chars().count()` 计算。
