## 传感器的零值与缺失值，不能靠一个 if 混在一起

设备网关汇报一批读数：有的被审核拒绝，有的暂时没有值，有的值恰好为 0。为了图表简洁，开发者一开始跳过所有不能累加的记录，最后却发现某些传感器彻底从报表中消失了。

需求其实包含两层：传感器是否出现在输入里，以及其中有多少条记录符合有效统计条件。`Some(0)` 不是 `None`，拒绝的读数不应加入合计，但该传感器仍可能需要保留一行零统计。再加上按名称排序和借用源数据，实验才真正覆盖了完整的数据语义。

当统计看起来都为零时，先问原因是“没有有效值”还是“没有这个设备”，不要只比较最后一个合计数字。

## 需求

传感器记录按输入顺序给出。每个不同的 `sensor` 都必须在返回的汇总中有且仅有一行，即使该传感器没有任何可累计读数。

只有 `accepted == true` 且 `value == Some(n)` 的记录参与统计。每条符合条件的记录使 `accepted_count` 加一，并将 `n` 加入 `total`。`Some(0)` 是一个有效读数，计数加一但总和不变；`None` 与 `accepted == false` 都不累计。未接受的记录仍使该传感器出现在结果中。

空切片返回空 Vec。结果按 `sensor` 的 Rust `str` 字典序升序排列。必须保持输入可再次读取；返回的服务名必须从输入借用。题设保证总和能由 `i64` 表示。

## 固定接口

```rust
pub fn summarize<'a>(readings: &[Reading<'a>]) -> Vec<SensorSummary<'a>>
```

使用 `HashMap` 做内部聚合是可行的，但它的遍历顺序不构成输出顺序。你可以把 map 汇总转成 Vec 后显式排序。禁止为了键查找或返回结果而无必要地复制 sensor 字符串。

## 先预测：零值不是缺失值

考虑以下记录：

| sensor | accepted | value | 应否累计 |
| --- | --- | --- | --- |
| alpha | true | Some(0) | 计数 +1，总和 +0 |
| alpha | false | Some(7) | 不累计，但仍是 alpha 的记录 |
| alpha | true | None | 不累计 |
| beta | true | Some(3) | 计数 +1，总和 +3 |

最终结果按 sensor 升序为 alpha（计数 1、总和 0），beta（计数 1、总和 3）。**先写出预期，再实现并运行测试**；不得只按 value 是否为非零判断记录有效性。

## 原理推导与反例辨析：处理传感器缺失

拒绝记录、无值、有效零值必须区分。 传感器汇总要区分无观测值、被拒绝的观测以及数值为零的有效观测；Option 和过滤顺序会影响结果语义。

`Some(0)` 是已经收到的有效零值，`None` 是没有读数；被拒绝的设备事件不应进入合计，但可能仍需在报告里留下该设备。只用最终总和判断正确性，很容易把三种状态混淆。

用 `unwrap_or(0)` 把缺失值改成零，会把“未观测”混入真实的零；先丢弃无值行又可能违背保留完整行的报告契约。 逐条插入被拒绝、无值、零值、负值与正常值，核对接受计数与总数；最后检查只有拒绝事件的传感器是否存在于结果。数值溢出和排序同样是不同的验收维度。

实际测试应该分别覆盖这些职责：创建有效零值、None、无效标记和普通数值四类记录，核对统计与完整报告行数。 复盘明确哪些记录计入聚合、哪些必须留在结果中，以及为何。

## 参考实现

[参考工程的完整 `src/lib.rs`](https://github.com/liulewis67-ops/rust_training/blob/main/content/samples/m08-reference/src/lib.rs) 可在本地通过全部公开测试，核心步骤是先为每个 sensor 建立默认行，再判断是否符合统计条件：

```rust
let entry = grouped.entry(reading.sensor).or_insert((0, 0));
if reading.accepted {
    if let Some(value) = reading.value {
        entry.0 += 1;
        entry.1 += value;
    }
}
```

最后将结果收集为 `Vec` 并按 sensor 升序排序。这个流程能保留只有拒绝记录的传感器，也能将 `Some(0)` 计为有效读数。

## 实践迁移：Some(0) 也属于有效传感器读数

**先预测：** `accepted=true, value=Some(0)` 与 `accepted=true, value=None` 都产生总和 0；是否意味着两者计数也相同？

**动手改造：** 在 M08 sensor starter 中先保留全部传感器的统计行，再只对 accepted 且有数值的读数增计数/总和。

**反例与边界：** 加入仅有拒绝记录的传感器、有效零值、负值与 Unicode 名称；不应因没有可累计数值而删除传感器行。

**验收证据：** 提供 alpha/beta/gamma 的结果表以及全部公开测试的通过证据，解释借用名称的来源。
