# M02-L04：数组、元组、模式与边界

> **本节核心问题：** 三个传感器读数用数组还是元组？怎样避免越界并完整分类？

**当前问题：** 一组样本和一条记录不是同一数据形状。

## 学习目标

- 说明元组可以把不同类型的固定数量值组合起来，数组保存固定长度、同一种类型的元素。
- 用元组索引或解构读取具名变量；用从 0 开始的数组下标访问元素。
- 使用 `match` 的字面量、范围和通配模式表达完整分类。
- 检查数组访问的上下界，并说明索引越界会触发运行时 panic。

## 场景：三个采样读数的统计与分级

一次采样包含恰好三个 `u8` 数字，既要取中间值又要归类分数。你需要选择有明确形状的数据结构，并把索引、范围和兜底分支写成可测试的契约。

**先预测：** 三元素数组的 `readings[3]` 会发生什么？下标 `3` 等于长度，不是合法位置；当越界索引在运行时实际执行，程序会 panic。对显然固定越界的索引，编译器或 lint 也可能提前诊断。

## 核心知识点一：元组表达异构固定结构

元组能把不同类型、固定数量的字段放进一个值中。短暂组合不同性质的数据时，可以逐位访问，也可以在 `let` 中一次解构：

```rust
/// Formats a fixed pair of coordinates using tuple indexing.
fn format_point(point: (i32, i32)) -> String {
    format!("({}, {})", point.0, point.1)
}

/// Adds the horizontal and vertical components of a point.
fn point_total(point: (i32, i32)) -> i32 {
    let (x, y) = point;
    x + y
}

/// Prints a point and the sum of its coordinates.
fn main() {
    let point = (4, -1);
    println!("{}; total={}", format_point(point), point_total(point));
}
```

元组里的位置从 `.0` 开始；解构则让每个位置有一个局部名字。二元组 `(4, -1)` 和一元组 `(4,)` 写法不同，单个值后面的逗号不能省略。字段含义很多或容易混淆时，不要靠长元组位置记忆业务含义；本课先练固定小结构。

## 核心知识点二：数组要求类型一致且长度固定

数组用 `[T; N]` 表示：全部元素同为 `T`，数量固定为 `N`。初始化时可以逐项列出，也可以用 `[value; count]` 重复一个值：

```rust
/// Returns the middle reading from a fixed three-value array.
fn middle_reading(readings: [u8; 3]) -> u8 {
    readings[1]
}

/// Computes the total of a fixed three-value array.
fn total_readings(readings: [u8; 3]) -> u16 {
    u16::from(readings[0]) + u16::from(readings[1]) + u16::from(readings[2])
}

/// Prints readings created with both array forms.
fn main() {
    let readings = [12_u8, 15, 14];
    let baseline = [0; 3];
    println!("middle={}, baseline={:?}", middle_reading(readings), baseline);
}
```

对于长度为 3 的数组，有效下标是 `0`、`1`、`2`；长度本身不是最后一个有效下标。数组下标表达式会进行边界检查，越界时程序在运行期 panic：

```rust
/// Reads an element using a caller-provided array position.
fn reading_at(readings: [i32; 3], position: usize) -> i32 {
    readings[position]
}

/// Demonstrates the first and last valid positions without panicking.
fn main() {
    let readings = [12, 15, 14];
    assert_eq!(reading_at(readings, 0), 12);
    assert_eq!(reading_at(readings, 2), 14);
}
```

`reading_at(readings, 3)` 是非法位置，会在执行索引时 panic。把调用放在 `if position < readings.len()` 的条件保护中，或限制调用方只传入 `0..readings.len()`，才能保证这段索引安全。检查边界时要分别看第一个位置、最后一个位置和刚好等于长度的位置；不要把“最后一个元素”误写成 `len`。

## 核心知识点三：用模式解构固定形状

元组和已知长度的数组都可以直接解构。模式左侧要和结构形状对应：

```rust
/// Returns the first and last values from a three-element array.
fn ends(values: [i32; 3]) -> (i32, i32) {
    let [first, _, last] = values;
    (first, last)
}

/// Demonstrates exact-shape destructuring for a known-size array.
fn main() {
    let (x, y) = (3, 5);
    let (first, last) = ends([x, 8, y]);
    println!("{first}, {last}");
}
```

`_` 表示这个位置需要匹配，但不需要给它绑定名字。`[first, _, last]` 要求这个数组形状恰好能由三个位置匹配；数组长度是类型的一部分。若把三元素数组写成只匹配两项的 `let [first, last] = values;`，该模式不能覆盖此数组，编译器会拒绝这项不可失败的 `let` 绑定。

## 核心知识点四：`match` 与边界分类

模式也可用于 `match`。每个分支指出要处理的值范围，最后用 `_` 覆盖其余值，保证所有可能输入都有归属：

```rust
/// Classifies a score using inclusive integer ranges.
fn score_band(score: u8) -> &'static str {
    match score {
        0..=59 => "needs review",
        60..=84 => "meets target",
        85..=100 => "strong",
        _ => "outside scale",
    }
}

/// Prints classifications for the lower and upper boundaries.
fn main() {
    println!("{} / {}", score_band(60), score_band(101));
}
```

整数模式范围 `a..=b` 同时包含两端。先核对题目的合法值域，再决定范围边界；`_` 只表示“其他所有值”，若这些值并不应该被悄悄归到同一类，就要改成清楚的诊断或让函数契约缩窄输入。本例用 `u8` 展示输入类型范围更大于业务量表的情形，因此显式标出 100 以外的值。

## 检验理解与边界检查

面对固定数据结构，先问每个字段是否同类型、数量是否会改变：不同类型的小组合可用元组，同类型固定数量可用数组。访问数组时记住下标从 0 起、有效区间排除长度。使用解构时核对形状；使用 `match` 时逐段检查上下界，并确保其他输入有明确处理方式。`Vec` 的动态长度和 `Option` 风格的可失败访问会在后续单元学习。

## 与 Java / Go 对比：数组长度和匹配形状

Rust 的 `[T; N]` 把元素类型和长度都写进类型；元组支持固定数量的不同类型。与 Java 数组及 Go 的数组/切片比较时，应注意**Rust 数组长度是类型的一部分**。

Rust `match` 需要穷尽匹配。`_` 虽能覆盖其余值，但不代表业务上允许将非法输入归入某个默认类别。

## 检验理解

**先预测再验证：** `ends([3, 8, 5])` 的结果是什么？`[first, _, last]` 和 `[first, last]` 哪个能匹配三元素数组？再对 `score_band(59)`、`(60)`、`(100)`、`(101)` 分别建立断言。

**验收标准：** 能判断元组/数组形状、解释 `0..len` 有效边界，并处理 `match` 的兜底分支。

## 实践迁移：采样分组与穷尽分类

**先预测：** 三个 `u8` 读数属于同类型数组；记录 `(时间戳, 状态, 数值)` 适合用同类型数组吗？

**动手改造：** 把固定数量采样放入数组，用元组表达不同角色，再用 `match` 对已约定的数值范围分类。

**反例与边界：** 检查第一个、最后一个合法索引和刚好越界的位置；新增类别时验证 `match` 是否遗漏分支。

**验收证据：** 列出三类输入各自的类型和分类结果，并保留一次越界保护断言。

## 本节小结

- 元组保存固定数量的异构值；数组保存固定长度的同类型值。
- 解构模式必须匹配结构形状；`_` 仅忽略某个位置的值。
- 索引可能在运行期越界，`match` 则必须穷尽模式并明确业务兜底语义。
