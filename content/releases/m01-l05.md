# M01-L05：实验——让一个失败项目重新通过

下载[实验起始项目 ZIP](./m01-l05-starter.zip)，解压到自己的电脑。项目使用 Rust 1.95.0、Edition 2024；先运行 `rustup toolchain install 1.95.0`。本实验练习从编译失败到测试失败，再到修复并复验的一条完整反馈循环。

## 学习目标与先修

完成本节后，你能区分编译错误与行为测试失败，利用诊断找到根因，保留公开测试并检查修复后的差异。先完成 M01-L03/L04，能够在 Cargo 项目目录运行命令。

## 题面与项目结构

起始项目计算整数分值的折扣。函数 `discounted_total_cents(subtotal_cents: i64, discount_percent: u8) -> i64` 的输入范围分别是 `0..=1_000_000` 与 `0..=100`。折扣分值向下取整，返回扣除折扣后的金额。ZIP 内有 `Cargo.toml`、`src/lib.rs` 和 `tests/public_contract.rs`，公开测试检查零折扣、10% 折扣与 100% 折扣。

## 本地操作与预期结果

在解压后的项目根目录运行：

```text
rustc +1.95.0 --version
cargo +1.95.0 check
cargo +1.95.0 test
```

先保存 `cargo check` 的诊断；起始代码应因类型不匹配报 E0308。只修复这个编译问题，再运行 `cargo test`：公开测试应出现 1 项通过、2 项失败。继续检查折扣比例计算，修复后再次运行 `cargo +1.95.0 test`，应有 3 项测试通过。最后运行 `cargo +1.95.0 fmt -- --check`，查看源码差异并说明每次修改对应的失败证据。这条失败和修复序列已在 Windows 的 Rust 1.95.0 上复现。

想重做时，先把个人修改另存到别处，再从原始 ZIP 解压到一个**新的空目录**；不要直接覆盖正在使用的项目。公开测试可以被任何人修改，因此本地绿色结果是自查证据，不是网站颁发的成绩。

## 分层提示

1. 第一处失败发生在编译阶段，先看赋值两侧的整数类型。
2. `u8` 到 `i64` 可以显式进行无损转换，不必放宽函数签名。
3. 折扣百分比的分母应与“百分之”对应；10% 的折扣不应把总额减为零。
4. 修复后同时检查 0%、10%、100%，再试一个折扣分值不是整数的输入。

## 参考实现

保留原函数签名与公开测试，将 `src/lib.rs` 的函数改成：

```rust
pub fn discounted_total_cents(subtotal_cents: i64, discount_percent: u8) -> i64 {
    let percent = i64::from(discount_percent);
    let discount_cents = subtotal_cents * percent / 100;
    subtotal_cents - discount_cents
}
```

例如 125 分打 10% 折扣，`125 * 10 / 100` 向下取整为 12 分，结果是 113 分。这个实现依赖题面给出的输入范围；超出范围的验证和溢出策略属于后续边界设计内容。

## 自查清单

- 初始编译错误、修复类型后的测试失败以及最终测试通过都能从原始 ZIP 重现。
- 没有删除测试、弱化断言或改变函数签名与输入契约。
- 能解释两次修复分别针对哪一条失败证据，并用 `cargo +1.95.0 test` 复验。
