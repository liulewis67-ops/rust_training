# M02-L05：实验——数据单位转换器

下载[实验起始项目 ZIP](./m02-l05-starter.zip)。这个小型库把十进制文本形式的整分钟转换为秒。起始版本有一个类型错误；修复编译后，再用公开测试定位输入与数值边界问题。

## 实验目标

- 根据 Cargo 诊断定位编译错误，再用测试区分正常值、零、非法输入和乘法溢出。
- 保持转换精度规则一致：输入只能是完整的非负十进制分钟数，结果是整秒，不做四舍五入。
- 对不能解析的输入和无法由 `u64` 表示的秒数返回 `Err`，不把无效值当零，也不让乘法溢出 panic。
- 记录每次失败与修改，并从发布的起始快照重新解压，复现一次相同修复。

## 输入与输出契约

输入必须是仅含 ASCII 数字的十进制 `u64` 分钟字符串，不接受正负号、空格或小数点。空字符串、非数字字符、负数和超出 `u64` 的文本属于非法输入。转换规则固定为 `秒数 = 分钟数 × 60`；`"0"` 是合法输入并得到 `Ok(0)`。若分钟可解析但乘以 60 超出 `u64`，函数也返回 `Err`。任何输入都不允许触发 panic。

## 任务步骤

1. 将起始 ZIP 解压到新的空目录，确认 `Cargo.toml` 位于项目根目录；记录 Rust/Cargo 版本。
2. 阅读 `README.md` 与公开测试，先运行 `cargo check` 并保存初始诊断。
3. 修复类型错误后运行 `cargo test`。逐项比较正常、零值、非法输入和溢出契约与实际行为。
4. 修复解析和乘法边界；不能把解析失败替换成零，也不能使用可能溢出的普通乘法。
5. 运行格式、构建与公开测试，记录输出并检查差异；不得删改公开测试来制造通过结果。
6. 保留原始 ZIP；要重做时解压到另一个新目录，再按记录复现修复。修复目录和起始项目彼此独立。

## 公开检查

公开测试覆盖 `"12"` 得到 `Ok(720)`、`"0"` 得到 `Ok(0)`，非法文本与负数返回 `Err`，以及可解析但乘法溢出的输入返回 `Err`。错误方案 `parse().unwrap_or(0)` 会把非法输入变成零；未检查的 `minutes * 60` 不能兑现溢出契约。参考实现和这些公开边界用例可直接查看。

## 提示

1. 先读类型诊断：文本解析不是直接得到 `u64`。
2. 把每个解析结果分成成功与失败两条路径；失败应保留为错误。
3. 乘法前检查是否有可表示结果；已知常数 60 可配合 `checked_mul`。
4. 覆盖恰好可表示的最大输入，以及紧邻其上的溢出输入。

## 公开参考实现

```rust
pub fn minutes_to_seconds(input: &str) -> Result<u64, &'static str> {
    if input.is_empty() || !input.bytes().all(|byte| byte.is_ascii_digit()) {
        return Err("minutes must contain only decimal digits");
    }

    let minutes = input
        .parse::<u64>()
        .map_err(|_| "minutes must be an unsigned whole number")?;
    minutes
        .checked_mul(60)
        .ok_or("seconds exceed the u64 range")
}
```

实现先限制输入字符为非空 ASCII 数字，再解析为 `u64`，最后使用 `checked_mul` 把溢出转换成 `Err`。它不接受 `+1`，因为题面要求输入只含数字字符。
