# M04-L04: Parameters, returns and partial moves

> **Guiding question:** Which fields remain usable after taking a String field out of a struct?

## Learning objectives

- By-value parameters transfer ownership of their non-Copy inputs into the function.

- Moving a non-Copy field can partially move a struct; untouched Copy fields may remain readable, but the whole value may no longer be usable.

- Reconstruct an owned result by deliberately supplying the moved fields and any remaining data.

## Scenario: Parameters, returns and partial moves

## Code walkthrough

Original code excerpts are preserved. Some deliberately demonstrate compile errors; predict what fails and compile each independently.

### Example 1

```rust
/// Owns the title and body of a message.
struct Message {
    title: String,
    body: String,
}

/// Consumes a message and returns its body to the caller.
fn take_body(message: Message) -> String {
    let title = message.title;
    println!("received: {title}");
    message.body
}

/// Receives the returned field under a new owner.
fn main() {
    let message = Message {
        title: String::from("build"),
        body: String::from("ready"),
    };
    let body = take_body(message);
    println!("returned: {body}");
}
```

### Example 2

```rust
/// Owns a title and body as separate String fields.
#[derive(Debug)]
struct Message {
    title: String,
    body: String,
}

/// Tries to use a partially moved structure as a whole.
fn invalid_use(message: Message) {
    let title = message.title;
    println!("title: {title}");
    println!("body: {}", message.body);
    println!("whole message: {message:?}");
}
```

### Example 3

```rust
/// Owns a title and body as separate String fields.
struct Message {
    title: String,
    body: String,
}

/// Consumes an old message and returns a complete updated message.
fn add_prefix(message: Message, prefix: String) -> Message {
    let title = format!("{prefix}{}", message.title);
    Message {
        title,
        body: message.body,
    }
}

/// Receives the complete value returned by the function.
fn main() {
    let original = Message {
        title: String::from("compile"),
        body: String::from("ready"),
    };
    let updated = add_prefix(original, String::from("CI: "));
    println!("{} / {}", updated.title, updated.body);
}
```

### Example 4

```text
caller Message ──move──> parameter message
caller prefix  ──move──> parameter prefix
message.title + prefix ──> new title
message.body ───────────> returned Message.body
returned Message ──move──> caller binding updated
```

## Java / Go comparison

Java and Go can copy or alias fields differently. Rust's partial-move rules turn an API's data-flow choices into compile-time constraints.

## Practice transfer: Reassemble a partially moved ticket

**Predict:** After moving the String body, can a Copy status still be read? Can the entire original ticket be passed again?

**Implement:** Extract body text, inspect untouched fields and construct a new complete ticket.

**Counterexample and boundaries:** Try to reuse the partially moved whole struct and examine the diagnostic; note extra constraints for types implementing Drop.

**Acceptance evidence:** Compile and test the reconstructed fields without cloning the entire ticket.
