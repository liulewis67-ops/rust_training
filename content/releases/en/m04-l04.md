## Code walkthrough

Original code excerpts are preserved. Some deliberately demonstrate compile errors; predict what fails and compile each independently.

### Example 1

```rust
/// Owns the title and body of a message.
struct Message {
    title: String,
    body: String,
}

/// Consumes a message and returns its body to the caller.
fn take_body(message: Message) -> String {
    let title = message.title;
    println!("received: {title}");
    message.body
}

/// Receives the returned field under a new owner.
fn main() {
    let message = Message {
        title: String::from("build"),
        body: String::from("ready"),
    };
    let body = take_body(message);
    println!("returned: {body}");
}
```

### Example 2

```rust
/// Owns a title and body as separate String fields.
#[derive(Debug)]
struct Message {
    title: String,
    body: String,
}

/// Tries to use a partially moved structure as a whole.
fn invalid_use(message: Message) {
    let title = message.title;
    println!("title: {title}");
    println!("body: {}", message.body);
    println!("whole message: {message:?}");
}
```

### Example 3

```rust
/// Owns a title and body as separate String fields.
struct Message {
    title: String,
    body: String,
}

/// Consumes an old message and returns a complete updated message.
fn add_prefix(message: Message, prefix: String) -> Message {
    let title = format!("{prefix}{}", message.title);
    Message {
        title,
        body: message.body,
    }
}

/// Receives the complete value returned by the function.
fn main() {
    let original = Message {
        title: String::from("compile"),
        body: String::from("ready"),
    };
    let updated = add_prefix(original, String::from("CI: "));
    println!("{} / {}", updated.title, updated.body);
}
```

### Example 4

```text
caller Message ──move──> parameter message
caller prefix  ──move──> parameter prefix
message.title + prefix ──> new title
message.body ───────────> returned Message.body
returned Message ──move──> caller binding updated
```

## Reason through a counterexample: Extract and rebuild entities

**Problem:** Extracting a struct field changes which parts remain usable.

**Principle and deduction:** A struct can be partially moved: non-Copy fields that moved are unavailable while untouched fields may remain usable; types implementing Drop have additional restrictions.

**Example and evidence:** Verify with the existing Rust example or lab: Remaining fields are preserved after a move.

**Counterexample:** Treating every field extraction as an entire-object move misses valid remaining-field uses; reusing the moved field is still invalid.

**Independent exercise:** Move a String out of a ticket struct, read its remaining integer field, then intentionally reuse the moved field. Compare reconstruction and cloning.
