# M05-L01: Shared and exclusive borrowing

> **Guiding question:** Why can two readers coexist but not overlap with a writer to the same value?

## Learning objectives

- &T lends read access without changing the owner; multiple shared borrows may coexist.

- &mut T lends exclusive mutable access; overlapping incompatible uses of the same data are rejected.

- Order reads and writes deliberately so the last use of a shared reference precedes the mutable operation.

## Scenario: Shared and exclusive borrowing

A configuration must be logged for auditing and then updated. Holding an old &String while modifying the same String causes a conflict.

## Core concept 1: Borrowing contract

&T lends read access without changing the owner; multiple shared borrows may coexist.

## Core concept 2: Lifetime and access implications

&mut T lends exclusive mutable access; overlapping incompatible uses of the same data are rejected.

## Core concept 3: API and boundary checks

Order reads and writes deliberately so the last use of a shared reference precedes the mutable operation.

## Code walkthrough

Source Rust snippets are unchanged; intentional borrow-checker failures are study material, not runnable examples to concatenate into one file.

### Example 1

```rust
/// Reads one String through two shared references.
fn main() {
    let message = String::from("review");
    let first = &message;
    let second = &message;
    println!("{first} and {second}");
    println!("owner still has: {message}");
}
```

### Example 2

```rust
/// Tries to mutate a String through a shared reference.
fn main() {
    let message = String::from("review");
    let shared = &message;
    shared.push_str("ed");
    println!("{shared}");
}
```

### Example 3

```rust
/// Appends text through an exclusive mutable reference.
fn main() {
    let mut message = String::from("review");
    let exclusive = &mut message;
    exclusive.push_str("ed");
    println!("{exclusive}");
}
```

### Example 4

```rust
/// Creates conflicting shared and exclusive borrows of one String.
fn main() {
    let mut message = String::from("review");
    let shared = &message;
    let exclusive = &mut message;
    exclusive.push_str("ed");
    println!("before: {shared}; after: {exclusive}");
}
```

### Example 5

```rust
/// Reads, then exclusively updates the same owned String.
fn main() {
    let mut message = String::from("review");
    {
        let shared = &message;
        println!("before: {shared}");
    }
    {
        let exclusive = &mut message;
        exclusive.push_str("ed");
    }
    println!("after: {message}");
}
```

### Example 6

```rust
/// Reads a label without taking its ownership.
fn show_label(label: &String) {
    println!("label: {label}");
}

/// Changes a value through an exclusive borrowed parameter.
fn add_suffix(text: &mut String) {
    text.push_str("!");
}

/// Keeps owning a String while borrowing it for two operations.
fn main() {
    let mut title = String::from("ready");
    show_label(&title);
    add_suffix(&mut title);
    println!("owner: {title}");
}
```
