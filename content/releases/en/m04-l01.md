# M04-L01: Owner, scope and Drop

> **Guiding question:** Who owns a resource and in what order do values leave scope?


## From domain models to resource ownership

M03 taught us to represent a task with structs, enums, and methods. The unresolved problem appears when its text crosses a function boundary: can the original caller still use the value? This is a consequence of connecting domain objects, not an unrelated syntax topic.

First trace scope and `Drop` here. M04-L02 explains moves, L03 compares Copy and Clone, and L04 applies these rules to parameters and return values. The lab and independent check then audit a text pipeline. M05 will ask how to access the same data without transferring ownership.

## Learning objectives

- Rust values have owners; a binding and its owned data are distinct concepts.

- When a scope ends, owned values are dropped in the language-defined order. Custom Drop runs before its fields are cleaned up.

- Draw an owner/value/resource graph rather than assuming a physical heap address represents ownership.

## Scenario: Owner, scope and Drop

A request handler acquires a temporary resource lease and another named object. Dropping the scope must not leave either resource alive accidentally.

## Code walkthrough

Original code excerpts are preserved. Some deliberately demonstrate compile errors; predict what fails and compile each independently.

### Example 1

```rust
/// Owns a label that makes scope cleanup visible in the output.
struct ResourceLease {
    name: String,
}

impl ResourceLease {
    /// Creates a lease with an owned label.
    fn new(name: &str) -> Self {
        Self {
            name: String::from(name),
        }
    }
}

impl Drop for ResourceLease {
    fn drop(&mut self) {
        println!("drop {}", self.name);
    }
}

/// Shows when owners leave nested scopes.
fn main() {
    let room = ResourceLease::new("room");
    {
        let first = ResourceLease::new("first");
        let second = ResourceLease::new("second");
        println!("inner scope ends");
    }
    println!("outer scope continues");
    println!("main scope ends");
}
```

## Java / Go comparison

Java garbage collection and Go GC/finalizers are different from Rust's deterministic ownership-based cleanup. Do not treat Drop like an arbitrary GC callback.
