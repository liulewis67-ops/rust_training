## Read a ticket before handing it away

A support handler needs the text's UTF-8 byte length before handing ownership to storage. Moving first makes the original unavailable; cloning merely to read a length is needless.

Borrow for metadata, then move the owned value when it is consumed. `str::len()` measures bytes, not visible characters. The finished exercise should prove both the business unit and the ownership flow.

## Learning objectives

- Reading a String through &str or &String need not move ownership.

- A by-value call can consume the ticket text after the read is complete.

## Reason through a counterexample: Audit ticket handling

Ticket metadata must be read before text is consumed. A ticket can be inspected through a borrow before its owned text is handed off; the previous binding cannot be used afterward.

For a support ticket, borrow text briefly to obtain its UTF-8 byte length before handing ownership to storage. Reversing those operations produces an error at the attempted use of the old binding.

Moving the String before computing its byte length causes a moved-value failure; byte length is also not always character count. Use a ticket containing Chinese characters to distinguish byte length from `chars().count()`, and show that measuring length does not require cloning. Then call the real consuming function and mark the last legal read.

To verify the data flow,Order inspection before hand-off, then test both ASCII and non-ASCII ticket labels for expected byte counts. Distinguish the end of a temporary read borrow from transfer of ownership.

## There is a read-only opportunity before handing the ticket away

A support-ticket function must return the original text's UTF-8 byte length and an owned string prefixed with `[ticket] `. Calling `render_ticket(source)` first, then `source.len()`, uses the old binding after the function has consumed its owned `String`. This is an ordering error, not a string-formatting bug.

The useful sequence is observe, then transfer: `.len()` requires only a brief shared borrow. Once the numeric length has been captured, the owned `source` can move into the renderer without being copied merely to preserve its metadata. A small integer and the original heap-backed string have different ownership responsibilities.

UTF-8 adds an essential boundary. `"é"` occupies two bytes despite representing one Unicode scalar value. If an implementation returns a character count, the formatted text can look perfectly correct while the public length contract is wrong. The examples `"build"`, `""`, and `"é"` distinguish ASCII, empty input, and multibyte content.

Independent delivery should prove that the final read happens before the move and that the returned text matches the formatting rule. Do not keep using the old binding after the transfer. If you introduce a full clone to quiet the compiler, explain what additional independent owner actually needs it.

## Reference implementation

Review after attempting the task; the source code is kept unchanged.

```rust
/// Returns the original UTF-8 byte count and the rendered ticket.
pub fn publish_ticket(source: String) -> (usize, String) {
    let byte_len = source.len();
    let ticket = render_ticket(source);
    (byte_len, ticket)
}

/// Consumes a ticket body and returns its rendered form.
fn render_ticket(body: String) -> String {
    format!("[ticket] {body}")
}
```
