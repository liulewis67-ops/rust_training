# M08-L06: Assessment: aggregation with borrowed sensor names

> **Guiding question:** Does a valid zero reading count as a reading, and should a rejected-only sensor disappear?

## Engineering thread: Handle sensor absence

**Carry forward:** The previous lesson, M08-L05, produced "Deterministic service summary."

**Current obstacle:** Rejected, absent, and valid zero readings differ.

**Decision to make:** Combine Option, filtering, and aggregation.

**Deliverable:** Sensor report preserving all rows. **Evidence:** Some(0) counts; rejected-only sensors retain rows.

**Why it leads forward:** In M09-L01, the next constraint is: Reports and config input can fail and must not become success.

## Reason through a counterexample: Handle sensor absence

**Problem:** Rejected, absent, and valid zero readings differ.

**Principle and deduction:** Sensor reports must distinguish missing readings, rejected readings and valid zero readings. Option and filter order encode those semantics.

**Example and evidence:** Verify using the lesson's code or lab: Some(0) counts; rejected-only sensors retain rows.

**Counterexample:** Using unwrap_or(0) for missing data conflates absence with real zero; dropping rows may violate a complete-report contract.

**Independent exercise:** Create zero, None, rejected and normal readings, then check totals and retained row count separately.

**Review:** State which records affect aggregation and which must remain visible in the report.

## Reference implementation

Read the reference only after running the starter tests.

```rust
let entry = grouped.entry(reading.sensor).or_insert((0, 0));
if reading.accepted {
    if let Some(value) = reading.value {
        entry.0 += 1;
        entry.1 += value;
    }
}
```
