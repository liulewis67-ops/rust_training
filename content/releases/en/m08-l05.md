## Reason through a counterexample: Repair service aggregation

**Problem:** Duplicate service names overwrite totals and map order is unstable.

**Principle and deduction:** Log aggregation separates duplicate-key accumulation from deterministic output ordering; HashMap::entry updates, while sorted Vec serves reporting.

**Example and evidence:** Verify using the lesson's code or lab: Repeated api totals and counts are correct.

**Counterexample:** Plain insert overwrites previous totals, and raw HashMap traversal cannot promise stable presentation order.

**Independent exercise:** Test api:10, web:2, api:5, empty input and Unicode service names, asserting totals and explicit sorted order.

**Review:** Separate internal storage choices from the public output guarantee.
