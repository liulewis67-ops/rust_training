# M07-L05: Lab: a replaceable parser interface

> **Guiding question:** Does implementing a shared parser trait guarantee that a parser uses the right delimiter?


## Integrating the ideas in the lab

- L01 **Extract shared bounds**: Express the capability with minimal generic bounds.
- L02 **Define a behavior contract**: Use trait and impl for consistent summary behavior.
- L03 **Choose dispatch strategy**: Compare static generic dispatch with dyn Trait.
- L04 **Protect conversion invariants**: Use newtypes and TryFrom to reject invalid conversions.

The task is now **Shared traits do not guarantee correct delimiter behavior.**. Define the contract and edge cases; reproduce the initial problem, apply **Repair parser behavior under an unchanged trait.**, and run the checks below. **Target: Replaceable configuration parsers.** Record why the implementation satisfies the contract, not just whether it compiles.

## Learning objectives

- A trait isolates parser call sites from the concrete delimiter-specific implementation.

- Behavior tests must verify that only the first delimiter separates the key from its value.

- An implementation can satisfy a type interface while violating its parsing contract.
