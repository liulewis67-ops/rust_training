## Learning objectives

- iter yields shared &T and preserves the collection's ownership.

- iter_mut yields exclusive &mut T for in-place changes without moving elements out.

- into_iter on an owned Vec consumes the collection and yields owned T; a previously owned binding cannot be used afterward.

## Code walkthrough

The source Rust snippets below are unchanged; some intentionally fail compilation or behavioral assertions to demonstrate a rule.

### Example 1

~~~rust
/// Reads labels through shared references and keeps the vector usable.
fn main() {
    let labels = vec![String::from("queued"), String::from("ready")];
    let mut iter = labels.iter();

    assert_eq!(iter.next().map(String::as_str), Some("queued"));
    assert_eq!(iter.next().map(String::as_str), Some("ready"));
    assert_eq!(iter.next(), None);
    assert_eq!(labels.len(), 2);
    assert_eq!(labels[0], "queued");
}
~~~

### Example 2

~~~rust
/// Adds a suffix to each label through exclusive element borrows.
fn main() {
    let mut labels = vec![String::from("queued"), String::from("ready")];

    for label in labels.iter_mut() {
        label.push('!');
    }

    assert_eq!(
        labels,
        vec![String::from("queued!"), String::from("ready!")]
    );
}
~~~

### Example 3

~~~rust
/// Owns a label that deliberately does not implement Clone.
#[derive(Debug, PartialEq)]
struct Label(String);

/// Transfers every label from the input vector into a result vector.
fn transfer_labels(labels: Vec<Label>) -> Vec<Label> {
    let mut transferred = Vec::with_capacity(labels.len());
    for label in labels.into_iter() {
        transferred.push(label);
    }
    transferred
}

/// Verifies that owned values can be transferred without cloning.
fn main() {
    let labels = vec![Label(String::from("queued")), Label(String::from("ready"))];
    let transferred = transfer_labels(labels);
    assert_eq!(
        transferred,
        vec![Label(String::from("queued")), Label(String::from("ready"))]
    );
}
~~~

### Example 4

~~~rust
/// Intentionally invalid: values is used after it is consumed.
fn main() {
    let values = vec![String::from("one")];
    let iter = values.into_iter();
    assert_eq!(iter.count(), 1);
    assert_eq!(values.len(), 1);
}
~~~

## Reason through a counterexample: Choose iteration ownership

**Problem:** Events may be read, edited in place, or consumed downstream.

**Principle and deduction:** iter yields shared references, iter_mut yields mutable references, and into_iter on an owned collection consumes elements. The choice depends on subsequent ownership needs.

**Example and evidence:** Verify using the lesson's code or lab: Consumed collections cannot be reused.

**Counterexample:** Using consuming into_iter merely to count elements prevents later reuse; trying to mutate through iter() violates access permissions.
