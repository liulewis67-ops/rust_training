## Reason through a counterexample: Handle units and overflow

**Problem:** Unit conversion can overflow a numeric type.

**Principle and deduction:** Unit conversion must include a numeric range contract. checked_mul returns Option for unrepresentable results rather than relying on build-mode-dependent overflow behavior.

**Example and evidence:** Compare with the existing code or lab and verify: Maximum safe and overflowing inputs have tests.

**Counterexample:** A valid u32 input does not imply value * 60 fits in u32; ignoring None discards failure information.

**Independent exercise:** Test zero, one, the largest supported minute count, and one past that boundary, predicting Some/None before running.

**Review:** Derive the accepted range from the target type instead of choosing an arbitrary cutoff.

## Reference implementation

Check the source solution only after working through the task.

```rust
pub fn minutes_to_seconds(input: &str) -> Result<u64, &'static str> {
    if input.is_empty() || !input.bytes().all(|byte| byte.is_ascii_digit()) {
        return Err("minutes must contain only decimal digits");
    }

    let minutes = input
        .parse::<u64>()
        .map_err(|_| "minutes must be an unsigned whole number")?;
    minutes
        .checked_mul(60)
        .ok_or("seconds exceed the u64 range")
}
```
