# M05-L02: Borrow ranges and non-lexical lifetimes

> **Guiding question:** Why can a reference name remain in scope while its borrow is already over?


## Mechanism, boundary and independent exercise

NLL follows the last use of a borrow, not merely the closing brace of a binding. Reading a vector element through a reference and then pushing is fine if that borrow is finished. Using the old reference after push conflicts with exclusive mutation, because vector storage may be reallocated—not because reallocation is guaranteed.

**Deeper exercise:** Predict the compile outcomes for read-then-push and push-then-read. Repair the second version by reordering, by cloning an owned snapshot, and by keeping an index then looking up again. Compare allocation cost, index validity assumptions, and clarity.

## Code walkthrough

Source Rust snippets are unchanged; intentional borrow-checker failures are study material, not runnable examples to concatenate into one file.

### Example 1

```rust
/// Uses a shared borrow before mutating the collection.
fn main() {
    let mut names = vec![String::from("Ada")];
    let first = &names[0];
    println!("first: {first}");
    names.push(String::from("Lin"));
    println!("count: {}", names.len());
}
```

### Example 2

```rust
/// Tries to use a shared reference after mutating its owner.
fn main() {

}
```

## Reason through a counterexample: Shorten borrow ranges

**Problem:** A reference binding can outlive its active borrow.

**Principle and deduction:** NLL can end a borrow at its last use even while the binding remains in scope.

**Example and evidence:** Check the original code or lab: Reordering read and write reproduces or fixes conflict.

**Counterexample:** A vector element reference used after push blocks exclusive mutation because reallocation is possible, not guaranteed.

**Independent exercise:** Compare read-then-push and push-then-read; repair by reordering, cloning, or storing an index, and compare costs.

**Review:** Identify the last actual use of the borrow, not only its declaration.
