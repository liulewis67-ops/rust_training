# M07-L02: Traits, impl and associated types

> **Guiding question:** Can two unrelated types with similarly named inherent methods satisfy T: Summary automatically?

## Learning objectives

- A trait defines shared method requirements; impl Trait for Type supplies that contract for each concrete type.

- Inherent impl Type methods are distinct from trait implementations even when names match.

- Associated types describe implementation-specific related types; choose them deliberately instead of duplicating generic parameters.

## Code walkthrough

The original Rust examples are preserved. A snippet designed to fail compilation must be checked separately; behavior still requires tests.

### Example 1

```rust
/// Describes a value that can produce a displayable summary.
trait Summary {
    type Output: std::fmt::Display;

    /// Produces the summary chosen by each implementation.
    fn summarize(&self) -> Self::Output;
}
```

### Example 2

```rust
/// Stores a queue item's owned fields.
struct QueueItem {
    code: String,
    retries: u8,
}

/// Adds constructors that belong specifically to QueueItem.
impl QueueItem {
    /// Creates a queue item from its code and retry count.
    fn new(code: String, retries: u8) -> Self {
        Self { code, retries }
    }
}

/// Implements the shared summary contract for QueueItem.
impl Summary for QueueItem {
    type Output = String;

    /// Formats both fields for a human-readable log line.
    fn summarize(&self) -> Self::Output {
        format!("{} (retries: {})", self.code, self.retries)
    }
}
```

### Example 3

```rust
/// Stores the number of imported rows.
struct ImportBatch {
    rows: u32,
}

/// Summarizes a batch with a compact numeric result.
impl Summary for ImportBatch {
    type Output = u32;

    /// Returns the number of rows as its summary.
    fn summarize(&self) -> Self::Output {
        self.rows
    }
}

/// Uses only the shared trait contract and its output bound.
fn render_summary<T: Summary>(value: &T) -> String {
    value.summarize().to_string()
}

/// Exercises one shared function with two implementation types.
fn main() {
    let item = QueueItem::new(String::from("Q17"), 2);
    let batch = ImportBatch { rows: 8 };
    assert_eq!(render_summary(&item), "Q17 (retries: 2)");
    assert_eq!(render_summary(&batch), "8");
}
```

### Example 4

```rust
/// This implementation is intentionally missing its required method.
impl Summary for QueueItem {
    type Output = String;
}
```

## Java / Go comparison

Java interfaces and Go method sets provide useful analogies, but Rust trait implementation and associated types are explicit obligations.

## Practice transfer: Prove an actual shared interface

**Predict:** If two types define summary() as inherent methods, do they implement a trait named Summary?

**Implement:** Implement a shared trait on two business models and call it from a generic function.

**Counterexample and boundaries:** Remove a required method or mismatch its associated type to observe a compile-time implementation error.

**Acceptance evidence:** List concrete implementations and output assertions, plus the initial diagnostic.
