# M07-L02: Traits, impl and associated types

> **Guiding question:** Can two unrelated types with similarly named inherent methods satisfy T: Summary automatically?


## Mechanism, boundary and independent exercise

An associated type expresses that a trait implementation fixes one output type (for example, NumberParser has Output=u32). Generic trait parameters instead allow separate parameterized implementations when appropriate. The associated type is established at compile time, not selected per runtime call.

**Deeper exercise:** Define trait ParseValue { type Output; fn parse(&self, input: &str) -> Option<Self::Output>; }. Implement NumberParser with Output=u32 and test 42 versus bad; add BoolParser. Then change Output to String without updating the method and predict the type mismatch.

## One summary interface for two domain types

A queue holds alerts and task events. Consumers need summaries but should not need to know each struct's field layout. Exporting every field and duplicating string assembly across callers becomes brittle as types evolve.

A trait states a shared behavioral contract; implementations supply type-specific logic. Associated types can represent outputs naturally tied to an implementation, while inherent methods still serve specialized operations. Ask what happens when a third event source arrives: a stable shared interface should reduce the number of callers that must change.

## Code walkthrough

The original Rust examples are preserved. A snippet designed to fail compilation must be checked separately; behavior still requires tests.

### Example 1

```rust
/// Describes a value that can produce a displayable summary.
trait Summary {
    type Output: std::fmt::Display;

    /// Produces the summary chosen by each implementation.
    fn summarize(&self) -> Self::Output;
}
```

### Example 2

```rust
/// Stores a queue item's owned fields.
struct QueueItem {
    code: String,
    retries: u8,
}

/// Adds constructors that belong specifically to QueueItem.
impl QueueItem {
    /// Creates a queue item from its code and retry count.
    fn new(code: String, retries: u8) -> Self {
        Self { code, retries }
    }
}

/// Implements the shared summary contract for QueueItem.
impl Summary for QueueItem {
    type Output = String;

    /// Formats both fields for a human-readable log line.
    fn summarize(&self) -> Self::Output {
        format!("{} (retries: {})", self.code, self.retries)
    }
}
```

### Example 3

```rust
/// Stores the number of imported rows.
struct ImportBatch {
    rows: u32,
}

/// Summarizes a batch with a compact numeric result.
impl Summary for ImportBatch {
    type Output = u32;

    /// Returns the number of rows as its summary.
    fn summarize(&self) -> Self::Output {
        self.rows
    }
}

/// Uses only the shared trait contract and its output bound.
fn render_summary<T: Summary>(value: &T) -> String {
    value.summarize().to_string()
}

/// Exercises one shared function with two implementation types.
fn main() {
    let item = QueueItem::new(String::from("Q17"), 2);
    let batch = ImportBatch { rows: 8 };
    assert_eq!(render_summary(&item), "Q17 (retries: 2)");
    assert_eq!(render_summary(&batch), "8");
}
```

### Example 4

```rust
/// This implementation is intentionally missing its required method.
impl Summary for QueueItem {
    type Output = String;
}
```

## Reason through a counterexample: Define a behavior contract

**Problem:** Similarly named methods do not form a shared interface.

**Principle and deduction:** A trait specifies behavior, an impl fulfills it for a concrete type, and an associated type fixes a related type at the implementation level.

**Example and evidence:** Verify with the existing example or lab: Distinct types satisfy the same contract.

**Counterexample:** Similarly named inherent methods do not establish a generic interface; an associated-type mismatch violates the declared contract.

**Independent exercise:** Define a summary trait, implement it for two types, call both through one generic function, then remove an impl to observe the diagnostic.

**Review:** Distinguish inherent methods, trait implementations and associated types.
