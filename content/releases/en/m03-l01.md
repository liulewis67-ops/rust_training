An order contains dimensions and state that must be updated consistently. A named struct makes field meaning explicit, while methods expose the intended behavior.

### Example 3

```rust
/// Represents a rectangle with bounded dimensions.
pub struct Rectangle {
    pub width: u16,
    pub height: u16,
}

/// Defines calculations and updates for rectangles.
impl Rectangle {
    /// Returns the area of the rectangle.
    pub fn area(&self) -> u32 {
        u32::from(self.width) * u32::from(self.height)
    }

    /// Replaces the width while leaving the height unchanged.
    pub fn set_width(&mut self, width: u16) {
        self.width = width;
    }

    /// Returns whether this rectangle contains the other rectangle.
    pub fn can_fit(&self, other: &Rectangle) -> bool {
        self.width >= other.width && self.height >= other.height
    }
}

/// Demonstrates read-only and mutable method calls.
fn main() {
    let mut outer = Rectangle {
        width: 10,
        height: 6,
    };
    let inner = Rectangle {
        width: 4,
        height: 3,
    };
    println!("{} {}", outer.area(), outer.can_fit(&inner));
    outer.set_width(3);
    println!("{}", outer.area());
}
```

## Java / Go comparison

Java classes and Go structs can express similar domain models. Rust makes the receiver's access permissions part of each method's signature.

## Practice transfer: Preserve a struct invariant

**Predict:** If width and height must never both be zero, is it safe to expose both as freely writable fields?

**Implement:** Separate validated construction, read-only queries and a controlled &mut self update method.

**Counterexample and boundaries:** Test a valid initial state, a rejected update and preservation of the previous state.

**Acceptance evidence:** Public API assertions plus proof that private internal fields cannot be accessed from a sibling module.
