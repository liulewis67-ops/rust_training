## Presence and state are two different questions

A reminder may not exist at all, or it may be pending, expired, or completed. Mapping absence to a default state collapses two distinct facts, making later behavior harder to reason about.

Use `Option` for whether the record exists and an enum for the exclusive state of an existing record. Then test absence, valid empty content, just-expired conditions, and the exact boundary time. The point is to explain why each action follows from the modeled state, not merely to write an exhaustive `match`.

## Reason through a counterexample: Deliver reminder state

**Problem:** Missing lookup and lifecycle state are separate decisions.

**Principle and deduction:** Reminder behavior combines lookup presence and lifecycle state. None means no task, not a valid task state.

**Example and evidence:** Use the existing sample or lab to verify: None and each lifecycle state have distinct assertions.

**Counterexample:** Matching only status and turning missing lookup into a default completed action misleads callers; wildcard arms can conceal unreviewed states.

**Independent exercise:** Build a decision table for missing, queued, running and finished tasks; assert the action for each row.

**Review:** Check whether distinct business conditions are accidentally collapsed into one result.

## Reference implementation

Review after completing the task.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AlertStatus {
    Queued,
    Claimed,
    Delivered { attempts: u8 },
    Cancelled { by_user: bool },
}

pub fn next_action(status: Option<AlertStatus>) -> &'static str {
    match status {
        None => "not found",
        Some(AlertStatus::Queued) => "claim",
        Some(AlertStatus::Claimed) => "deliver",
        Some(AlertStatus::Delivered { attempts }) => {
            if attempts < 2 { "retry" } else { "archive" }
        }
        Some(AlertStatus::Cancelled { by_user: true }) => "close",
        Some(AlertStatus::Cancelled { by_user: false }) => "review",
    }
}
```
