# M03-L04: Modules, visibility and public APIs

> **Guiding question:** Should every field of a task object be pub just because another module needs one operation?

## Engineering thread: Define module boundaries

**Carry forward:** The previous lesson, M03-L03, produced "Lookup API with explicit absence."

**Current obstacle:** Callers must not mutate arbitrary internal fields.

**Decision to make:** Expose stable methods, not internal representation.

**Deliverable:** Minimal public domain interface. **Evidence:** Direct writes to private fields are rejected.

**Why it leads forward:** In M03-L05, the next constraint is: Correct types do not guarantee correct task-list behavior.

## A module boundary protects future changes

A task list starts as a tiny library whose every field is public. Callers soon begin changing state arbitrarily, and any internal refactor requires scanning the entire repository for dependencies.

Visibility defines what the outside world may rely on. Expose creation, querying, and validated state transitions, not necessarily every storage detail. Treat `pub` as a compatibility promise rather than a shortcut. A small public API can make invariants easier to enforce and future changes safer.

## Learning objectives

- Modules organize namespaces and paths; declarations are private unless visibility is explicitly granted.

- pub on an item does not automatically open every enclosing module or every private field.

- Expose a narrow stable operation instead of making internal representation part of the public contract.

### Example 1

```rust
/// Exposes task operations while keeping the state representation internal.
pub mod task_api {
    enum State {
        Open,
        Closed,
    }

    pub struct Task {
        pub id: u32,
        state: State,
    }

    impl Task {
        /// Creates an open task with the supplied identifier.
        pub fn new(id: u32) -> Self {
            Self {
                id,
                state: State::Open,
            }
        }

        /// Closes the task through the public interface.
        pub fn close(&mut self) {
            self.state = State::Closed;
        }

        /// Reports whether the task is closed.
        pub fn is_closed(&self) -> bool {
            matches!(self.state, State::Closed)
        }

        /// Reopens a task for an internal workflow.
        fn reopen(&mut self) {
            self.state = State::Open;
        }
    }
}

/// Uses only the task API exposed to sibling modules.
mod client {
    fn print_task() {
        let mut task = crate::task_api::Task::new(17);
        println!("{} {}", task.id, task.is_closed());
        task.close();
        println!("{} {}", task.id, task.is_closed());
    }

    /// Runs the client-side example.
    pub fn run() {
        print_task();
    }
}

/// Runs the module API example.
fn main() {
    client::run();
}
```

### Example 2

```rust
/// Exposes a small counter API without exposing its stored value.
pub mod counter {
    pub struct Counter {
        value: u16,
    }

    impl Counter {
        /// Creates a counter at the requested starting value.
        pub fn new(value: u16) -> Self {
            Self { value }
        }

        /// Reads the current value.
        pub fn value(&self) -> u16 {
            self.value
        }

        /// Advances the counter by one without exceeding u16::MAX.
        pub fn advance(&mut self) {
            if self.value < u16::MAX {
                self.value += 1;
            }
        }
    }
}

/// Uses the counter without reaching into its representation.
fn main() {
    let mut counter = counter::Counter::new(4);
    counter.advance();
    println!("{}", counter.value());
}
```

### Example 3

```rust
/// Exposes a task with one public state transition.
pub mod task_api {
    enum State {
        Open,
        Closed,
    }

    pub struct Task {
        state: State,
    }

    impl Task {
        /// Creates a closed task.
        pub fn new_closed() -> Self {
            Self {
                state: State::Closed,
            }
        }

        /// Reopens a task for an internal workflow only.
        fn reopen(&mut self) {
            self.state = State::Open;
        }
    }
}

/// Attempts an operation unavailable to outside callers.
mod client {
    pub fn reopen_task() {
        let mut task = crate::task_api::Task::new_closed();
        task.reopen();
    }
}

fn main() {
    client::reopen_task();
}
```

## Reason through a counterexample: Define module boundaries

**Problem:** Callers must not mutate arbitrary internal fields.

**Principle and deduction:** Module visibility protects abstraction boundaries: private representation can evolve while public behavior remains stable.

**Example and evidence:** Use the existing sample or lab to verify: Direct writes to private fields are rejected.

**Counterexample:** Making all fields pub allows callers to bypass validation even when the intended constructor is correct.

**Independent exercise:** Privatize a field, expose a constructor and guarded update method, and try accessing the field from a sibling module to observe the error.

**Review:** Visibility limits who may mutate representation; it does not automatically establish every business invariant.
