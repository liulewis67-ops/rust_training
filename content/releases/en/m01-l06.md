# M01-L06: Assessment: deliver a testable Rust program

> **Guiding question:** Can you independently deliver a small program from an empty Cargo directory?

## Engineering thread: Deliver a tool

**Carry forward:** The previous lesson, M01-L05, produced "Repaired project with passing tests."

**Current obstacle:** The workflow must work without a prepared scaffold.

**Decision to make:** Build an integer-cents formatting CLI and library from scratch.

**Deliverable:** Reproducible CLI and verification report. **Evidence:** Zero/boundary formatting and local checks are recorded.

**Why it leads forward:** In M02-L01, the next constraint is: The CLI needs explicit numeric types and mutable counters.

## An empty directory is closer to a real request

Real requests rarely arrive with all the signatures and test fixtures filled in. Someone may simply ask for a command-line tool. Start by defining inputs, output, failure modes, and an acceptance command, not by guessing the implementation.

Create a Cargo project, verify one executable path, and add reproducible success and failure tests. `cargo run` demonstrates behavior along one route; `cargo test` should exercise a contract. Finally follow your own instructions from a clean directory. A delivery is complete only when another person can reproduce it.

## Learning objectives

- Set up a package with a library and binary boundary

- Write real tests before the implementation

- Run reproducible checks from a clean directory

## Prerequisites

Finish the preceding lesson and be able to run Cargo commands locally. Examples follow the Rust 1.95.0 / Edition 2024 course baseline.

## Scenario: Assessment: deliver a testable Rust program

Implement a cents-to-decimal formatter that returns exactly two fractional digits without relying on floating-point rounding.

## Model money in integer minor units

Divide the cents by 100 for the whole part and use the remainder for two-digit fractional formatting.

## Keep formatting testable

A pure library function is simpler to test than stdout and process arguments; the CLI can call it.

## Deliver evidence, not only source

Document cargo check/test/fmt outcomes and show input-output cases for the required numeric boundaries.

## Java / Go comparison

Like a small Java or Go CLI, keep the core formatting function separate from the entry point. Rust's type system helps but output formatting must be checked with assertions.

## Reason through a counterexample: Deliver a tool

**Problem:** The workflow must work without a prepared scaffold.

**Principle and deduction:** Independent delivery begins with an empty package and a stated input/output contract; it must not depend on the lab's prepared defects.

**Example and evidence:** Use the example or starter above to check: Zero/boundary formatting and local checks are recorded.

**Counterexample:** A CLI printout that looks right is not a substitute for library assertions over boundary values.

**Independent exercise:** Create a lib-plus-bin project from scratch, test zero and formatting boundaries, and record check/test/fmt verification steps.

**Review:** A classmate should be able to reproduce the result from your instructions on a clean checkout.

## Reference implementation

Read this only after attempting the lab and recording the initial failure.

pub fn format_cents(amount_cents: u32) -> String {

}
