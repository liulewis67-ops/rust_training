# M04-L02: Where a move occurs

> **Guiding question:** Why is a String unusable at its old binding after passing it by value?

## Learning objectives

- Assigning a non-Copy value can move ownership from one binding to another.

- Passing String to a by-value parameter moves it into the callee; returning it transfers ownership again.

- E0382 points to a moved value later used through its invalidated old binding.

## Prerequisites

Finish the previous lesson. Run examples against Rust 1.95.0 / Edition 2024 in a local Cargo project.

## Scenario: Where a move occurs

A request's owned log message passes through a rendering function. The caller must decide whether to transfer ownership or only lend access.

## Core concept 1: Owner and value

Assigning a non-Copy value can move ownership from one binding to another.

## Core concept 2: API consequences

Passing String to a by-value parameter moves it into the callee; returning it transfers ownership again.

## Core concept 3: Verification strategy

E0382 points to a moved value later used through its invalidated old binding.

## Code walkthrough

Original code excerpts are preserved. Some deliberately demonstrate compile errors; predict what fails and compile each independently.

### Example 1

```rust
/// Transfers a string to a new binding.
fn main() {
    let first = String::from("map");
    let second = first;
    println!("{second}");
}
```

### Example 2

```rust
/// Tries to use the source binding after moving its String.
fn main() {
    let first = String::from("map");
    let second = first;
    println!("{first}");
    println!("{second}");
}
```

### Example 3

```text
before assignment:
binding `first` ──owns──> String value ──owns──> heap buffer "map"

after `let second = first`:
binding `first`   (moved-from; cannot use the String)
binding `second` ──owns──> same String value ──owns──> same heap buffer "map"
```

### Example 4

```rust
/// Prints a label after taking ownership of it.
fn print_label(label: String) {
    println!("label: {label}");
}

/// Transfers the label to the function.
fn main() {
    let task = String::from("review");
    print_label(task);
}
```

### Example 5

```rust
/// Takes ownership of the label and prints it.
fn print_label(label: String) {
    println!("label: {label}");
}

/// Tries to reuse the caller binding after a by-value call.
fn main() {
    let task = String::from("review");
    print_label(task);
    println!("after call: {task}");
}
```

### Example 6

```rust
/// Prints a label and returns its ownership to the caller.
fn announce_and_return(label: String) -> String {
    println!("label: {label}");
    label
}

/// Receives the returned owner under a new binding.
fn main() {
    let task = String::from("review");
    let task = announce_and_return(task);
    println!("available: {task}");
}
```

### Example 7

```rust
/// Moves a local String into a return binding.
fn make_label() -> String {
    let local = String::from("review");
    let returned = local;
    println!("still local: {local}");
    returned
}

/// Tries to use a value after moving it toward the return expression.
fn main() {
    println!("{}", make_label());
}
```

## Java / Go comparison

Java references and Go value assignments differ from Rust ownership rules; an owned String move is a semantic transfer, not a guaranteed runtime heap copy.
