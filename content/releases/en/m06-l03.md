# M06-L03: Borrowed structs versus owned return values

> **Guiding question:** Should a parsed record stored in a background queue still borrow request text?

## Engineering thread: Choose borrowed or owned results

**Carry forward:** The previous lesson, M06-L02, produced "Checkable two-input borrow function."

**Current obstacle:** Immediate preview and queued work need different lifetimes.

**Decision to make:** Design view-style and owned-style results separately.

**Deliverable:** View and queue DTO interfaces. **Evidence:** Queued results survive input release.

**Why it leads forward:** In M06-L04, the next constraint is: Long-term ownership does not imply a static reference.

## Scenario: Borrowed structs versus owned return values

The same parsed configuration is sometimes inspected immediately and sometimes retained beyond the input's scope. Those callers have different ownership needs.

## Code walkthrough

Preserved Rust source examples include deliberate compile-time failures. Test each separately, identify the true owner and do not try to fix dangling data with an arbitrary lifetime name.

### Example 1

```rust
/// A view into an alert encoded in caller-owned text.
#[derive(Debug, PartialEq)]
struct AlertView<'source> {
    code: &'source str,
    detail: &'source str,
}

/// Parses two borrowed fields separated by the first vertical bar.
fn parse_alert_view(text: &str) -> Option<AlertView<'_>> {
    let (code, detail) = text.split_once('|')?;
    Some(AlertView { code, detail })
}

/// Keeps the source String alive while reading its parsed view.
fn main() {
    let raw = String::from("A17|queue delayed");
    let view = parse_alert_view(&raw).unwrap();
    println!("view: {} / {}", view.code, view.detail);
    println!("source remains: {raw}");
}
```

### Example 2

```rust
/// An alert whose fields are owned independently of the input.
#[derive(Debug, PartialEq)]
struct Alert {
    code: String,
    detail: String,
}

/// Parses an alert and creates owned copies of both fields.
fn parse_alert_owned(text: &str) -> Option<Alert> {
    let (code, detail) = text.split_once('|')?;
    Some(Alert {
        code: code.to_owned(),
        detail: detail.to_owned(),
    })
}

/// Retains the parsed alert after its source String has been dropped.
fn main() {
    let alert = {
        let raw = String::from("A18|cache rebuilt");
        parse_alert_owned(&raw).unwrap()
    };
    println!("owned: {} / {}", alert.code, alert.detail);
}
```

### Example 3

```rust
/// Invalid: the returned view would point into a local String.
fn invalid_alert() -> AlertView<'static> {
    let raw = String::from("A19|temporary");
    parse_alert_view(&raw).unwrap()
}
```

## Java / Go comparison

Java DTOs and Go structs may hide whether fields own or alias underlying buffers. Rust APIs can expose an explicit borrowed-versus-owned design.
