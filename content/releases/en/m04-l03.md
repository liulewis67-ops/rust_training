# M04-L03: Copy, Clone and cost

> **Guiding question:** Does a move always copy heap bytes, and is clone always free?

## Learning objectives

- Copy enables implicit duplication of suitable values such as u32, without invalidating the original binding.

- Clone is an explicit request for a type-specific duplicate; cloning an owned String generally allocates its own buffer.

- Move expresses ownership transfer, not a promise that bytes physically relocate.

## Code walkthrough

Original code excerpts are preserved. Some deliberately demonstrate compile errors; predict what fails and compile each independently.

### Example 1

```rust
/// Shows that assigning a Copy value leaves the source usable.
fn main() {
    let original = 12_u32;
    let assigned = original;
    println!("original: {original}, assigned: {assigned}");
}
```

### Example 2

```rust
/// Reports a copied scalar without consuming the caller's value.
fn report(level: u32) {
    println!("level: {level}");
}

/// Keeps using the scalar after passing it by value.
fn main() {
    let level = 3;
    report(level);
    println!("still available: {level}");
}
```

### Example 3

```rust
/// A small value whose fields are all Copy.
#[derive(Debug, Copy, Clone)]
struct GridPoint {
    x: i32,
    y: i32,
}

/// Copies a point on assignment.
fn main() {
    let first = GridPoint { x: 2, y: 5 };
    let second = first;
    println!("first: {first:?}; second: {second:?}");
}
```

### Example 4

```rust
/// Creates an explicit independent String clone.
fn main() {
    let mut original = String::from("draft");
    let mut duplicate = original.clone();
    original.push_str(" one");
    duplicate.push_str(" two");
    println!("original: {original}");
    println!("duplicate: {duplicate}");
}
```

### Example 5

```rust
/// Moves a String into a new binding without promising a physical relocation.
fn main() {
    let source = String::from("map");
    let destination = source;
    println!("{destination}");
}
```

## Java / Go comparison

Java object references, Go value copy and Rust Clone all have different performance and aliasing implications. Measure actual workloads rather than inferring cost from syntax.

## Practice transfer: Justify a necessary clone

**Predict:** Are assigning a u32 and calling String::clone both guaranteed to allocate heap storage?

**Implement:** Mark exactly where two independent owned strings are required, and replace unnecessary duplication with borrowing.

**Counterexample and boundaries:** Test empty and large strings but do not mistake one example for a benchmark.

**Acceptance evidence:** Report binding usability after Copy/Clone/move and which costs still require measurement.
