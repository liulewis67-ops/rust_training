# M05-L05：实验——零复制文本查询接口

下载[实验起始项目 ZIP](./public/m05-l05-starter.zip)，解压到新目录后阅读 README、快照清单和公开契约测试。起始函数尝试从两个输入引用返回一个切片，但没有说明返回切片借用哪个输入；项目应因缺少输出生命周期说明而不能通过 cargo check。

## 实验目标

- 实现零复制文本查询：按 Unicode 空白分隔并查找与查询词完全相同的 token。
- 对 String 借用视图和字符串字面量提供一致结果；命中时返回输入中的原始切片，未命中返回 None。
- 用函数签名表达输出切片来自文本输入，而不声称它来自查询字符串。
- 用类型和指针范围断言核验借用来源；审查查询路径没有创建新的 String 或收集临时 Vec。

## 行为契约

- 函数形状为 find_token<'text>(text: &'text str, query: &str) -> Option<&'text str>。
- 依 Unicode White_Space 切分输入，返回第一个与 query 完全相等的 token；不区分大小写、不做部分匹配。
- 输入 text 为 String 借用视图或字符串字面量时，命中和缺失语义相同。
- 命中时返回值是 text 的子切片，不能从 query 或局部新建文本返回。
- 函数不分配文本：查询不调用 to_owned、to_string、String::from，也不先 collect 到新集合。
- 空输入、全空白、无匹配均返回 None；U+3000 等 Unicode 空白按分隔符处理。
- 不联网、不读写文件、不使用第三方 crate；公开函数签名和测试保持不变。

## 实验步骤

1. 解压 ZIP，记录 ZIP SHA-256、starter-manifest.json、rustc 和 cargo 版本。
2. 执行 cargo check --offline，记录起始的缺少生命周期诊断；判断结果切片需要与哪个输入关联。
3. 修复函数签名，按需使用明确的文本输入生命周期，并从输入切片的 split_whitespace 迭代器返回匹配 token。
4. 执行 cargo test --offline，核对 String、字面量、Unicode 空白、缺失结果与原输入指针范围。
5. 验证错误方案：直接返回第一个 token 而不检查 query。项目应编译，但公开行为测试必须拒绝它。
6. 检查代码没有通过 to_owned、String::from 或临时集合复制文本；运行 cargo fmt -- --check、cargo check --offline 和 cargo test --offline。
7. 将起始 ZIP 解压到另一个新目录，逐项核对 manifest 文件哈希并复现起始编译错误；从重置副本再完成修复与验证。

## 借用与零复制证据

输出类型是 Option<&'text str>，编译器确认每个非空结果必须在 text 借用范围内有效；query 是另一输入，不决定返回切片寿命。公开测试进一步比较 token 指针与源文本地址区间，确认命中结果确实位于输入缓冲区内。函数体只遍历 split_whitespace 生成的原始子切片并比较，不构造拥有文本或临时 token 集合。

对照输入包含 String 和字面量，它们都可作为 &str 提供；函数不因输入的 owner 类型而改变查询行为。调用方仍需保证 String 在返回切片最后一次使用之前有效。

## 重置与验收边界

保留发行的错误起始 ZIP 和版本清单。需要重做时解压到新目录，核对 ZIP 与逐文件哈希后从原错误开始。重新解压仅用于本地重复练习，不提供代码隔离、提交历史或自动重置服务。

## 参考实现

```rust
pub fn find_token<'text>(text: &'text str, query: &str) -> Option<&'text str> {
    text.split_whitespace().find(|token| *token == query)
}
```

返回值由 `split_whitespace` 直接产生，是 `text` 的原始子切片；`find` 只比较，不创建新的文本或临时集合。显式生命周期标注说明返回切片来自 `text`，而不依赖 `query` 的有效期。
