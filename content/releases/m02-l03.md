# M02-L03：if、loop、while、for

> **本节核心问题：** 用 Rust 累加 1 到 N：怎样正确选择循环并避免漏算上界？

## 学习目标

- 根据条件选择 `if` 分支，并在需要结果时让两个分支产生相同类型的值。
- 区分 `loop`、`while` 与 `for` 的终止方式和适用场景。
- 为循环明确边界和更新路径，避免少算、多算或无法结束。
- 使用 `break` 提前结束循环；理解 `loop` 可以把 `break` 携带的值交给外层。

## 先修与环境

完成 M02-L02，能写函数、读懂块尾表达式和返回类型。本节用简单整数和布尔条件说明流程控制；数组与模式匹配留到后续单元。

## 场景：计算 1 到 N 的整数和

先用纸笔计算 `1 + 2 + 3 = 6`，再分别思考 `for`、`while` 与 `loop`。所有版本都必须回答：从哪里开始、什么时候停止、最后一个值算不算？

**先预测：** `1..3` 和 `1..=3` 各自遍历了哪些数？上界是否包含会直接影响结果。

## 核心知识点一：`if` 可以产生值

Rust 的 `if` 条件必须是 `bool`。条件成立时运行 `if` 后的块，否则进入可选的 `else` 块：

```rust
/// Chooses a label from a Boolean comparison.
fn temperature_label(celsius: i32) -> &'static str {
    if celsius >= 20 {
        "warm"
    } else {
        "cool"
    }
}

/// Prints the label selected by the conditional expression.
fn main() {
    println!("{}", temperature_label(18));
}
```

由于 `if` 会产生值，可以把它放在 `let` 右侧，也可以作为函数块的尾表达式。若两个分支都要作为同一个表达式的结果，它们必须兼容同一类型。下面的分支分别产生整数与字符串，编译器会报告类型不匹配：

```rust
/// This intentionally fails because the branches produce different types.
fn invalid_label(is_ready: bool) -> i32 {
    if is_ready {
        1
    } else {
        "waiting"
    }
}
```

如果只想执行动作、不需要分支值，可以让两个分支都返回 `()`，例如只在条件成立时调用 `println!`。不要把 Rust 的 `if` 当成自动转换真假的表达式；条件本身应明确写成布尔判断。

## 核心知识点二：让每种循环都有明确退出条件

### `while`：条件为真就继续

`while` 在每次迭代开始时检查条件。适合“还剩多少就继续”的流程：

```rust
/// Counts down from the starting value to zero.
fn count_down(mut remaining: u32) -> u32 {
    let mut ticks = 0;
    while remaining > 0 {
        remaining -= 1;
        ticks += 1;
    }
    ticks
}
```

这里循环变量在每轮递减，因此从 `3` 开始会执行三轮并返回 `3`。若漏掉 `remaining -= 1`，条件一直为真，循环无法结束。循环体修改的状态和退出条件应互相对应。

### `loop`：直到显式离开

`loop` 会重复执行，直到路径上遇到 `break`。当结束点需要从循环内部决定时，可以用它；普通重复计数则通常更适合 `for` 或 `while`。

```rust
/// Sums the integers from one through four and returns the sum via break.
fn sum_until_four() -> u32 {
    let mut next = 1;
    let mut total = 0;
    loop {
        if next > 4 {
            break total;
        }
        total += next;
        next += 1;
    }
}
```

`break total` 结束当前 `loop`，同时把 `total` 作为循环表达式的值交给函数尾部。可终止的 `loop` 中每个 `break` 值必须能合成一致结果类型。无 `break` 的无限循环不会把控制权返回到后续语句。

### `for`：遍历迭代器的每个元素

需要对已知范围逐项处理时，使用 `for` 和范围：

```rust
/// Sums a bounded inclusive integer range.
fn sum_one_to(limit: u32) -> u32 {
    let mut total = 0;
    for value in 1..=limit {
        total += value;
    }
    total
}

/// Prints a short inclusive sequence.
fn main() {
    for value in 1..=3 {
        println!("{value}");
    }
}
```

`1..=3` 包含两端；`1..3` 不包含上界。范围表达式实现迭代，循环变量由每轮的元素提供，不需要手动维护索引。上面的求和函数假定 `limit <= 100`，这样结果能放进 `u32`；数值边界属于函数契约的一部分。

## 核心知识点三：根据退出条件选择循环

选择前先说出“每轮取什么”和“何时停止”：

- 要遍历一个迭代器或范围，通常用 `for`，它不会因手动索引多一格而访问越界。
- 条件反复检查、循环状态决定是否继续，用 `while`，并检查循环体是否会推进状态。
- 退出点要在循环体中动态决定，或需要通过 `break value` 返回结果，用 `loop`；确保所有预期路径可到达正确的退出点。

三个构造都支持 `break` 和 `continue`。它们通常作用于最近的内层循环；标签可以显式选择外层循环，但本课的练习不需要嵌套标签。

## 检验理解与边界检查

逐项检查初始值、第一轮、最后一轮和零次迭代。对范围写明端点是包含还是排除；对 `while` 指出哪行让条件最终变假；对 `loop` 指出哪个分支执行 `break`。不要通过跳过一次迭代、硬编码最终答案或依赖超出题面范围的数据来“修好”循环。

## 与 Java / Go 对比：条件分支也能作为表达式

Java 常用三元表达式在两个结果之间选择，Go 更常将 `if` 写成控制语句。Rust 的 `if/else` 自身可以产生值，但两个分支必须返回兼容类型。Rust 的 `loop` 也可通过 `break value` 返回值。

按业务选择循环，而不是强行对齐 Java/Go 语法：固定范围偏向 `for`，条件反复变化时偏向 `while`，退出位置必须由循环内部确定时考虑 `loop`。

## 检验理解

**先预测再验证：** `sum_one_to(3)`、`sum_one_to(0)` 应返回什么？将 `1..=limit` 故意改为 `1..limit` 后，哪个测试会首先揭露漏算？然后修复并用 0、1、3、9 四个边界输入复验。

**验收标准：** 能指出 `while` 的推进语句、`loop` 的 `break` 路径，以及 `for` 的区间端点。

## 本节小结

- `if` 可以产生结果，分支值类型必须一致。
- `for`、`while`、`loop` 的差异主要是迭代方式与退出条件。
- 检查首轮、末轮、零次迭代和上界是否包含，才能发现边界问题。
