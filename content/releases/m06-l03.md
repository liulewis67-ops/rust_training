# M06-L03：带引用结构体与拥有型返回值

## 学完后

- 为持有字符串切片的结构体声明生命周期参数，并说明该结构体不能比输入切片活得更久。
- 实现零复制视图 API，让调用方持有输入 owner 并在其有效期内读取结构体字段。
- 在需要把结果保留到输入结束之后时，返回包含拥有型字段的结构体。
- 比较两种 API 的分配成本、数据复制和调用方持有责任，并按使用场景选择。

## 先修

完成 M06-L02，能把函数输入与返回引用的生命周期关系写入签名。本节用 `AlertView<'source>` 表达 borrowed fields，用 `Alert` 表达拥有字段；不讨论自引用结构体、`Cow` 或智能指针。

## 借用结构体：保留输入 owner，零复制查看字段

```rust
/// A view into an alert encoded in caller-owned text.
#[derive(Debug, PartialEq)]
struct AlertView<'source> {
    code: &'source str,
    detail: &'source str,
}

/// Parses two borrowed fields separated by the first vertical bar.
fn parse_alert_view(text: &str) -> Option<AlertView<'_>> {
    let (code, detail) = text.split_once('|')?;
    Some(AlertView { code, detail })
}

/// Keeps the source String alive while reading its parsed view.
fn main() {
    let raw = String::from("A17|queue delayed");
    let view = parse_alert_view(&raw).unwrap();
    println!("view: {} / {}", view.code, view.detail);
    println!("source remains: {raw}");
}
```

输出是 `view: A17 / queue delayed` 和 `source remains: A17|queue delayed`。`view` 两个字段分别借用 `raw` 的子切片。解析只创建一个小的 `AlertView` 值，不复制字段文本，也不分配新的字符串。调用方仍持有 `raw`，并必须让它在读取 `view` 时保持有效。

`AlertView<'source>` 中的 `'source` 是结构体类型的一部分：实例不能活得比保存于字段的引用更久。构造函数签名 `parse_alert_view(text: &str) -> Option<AlertView<'_>>` 把返回视图关联到唯一的文本输入；展开后也可以显式写成 `fn parse_alert_view<'source>(text: &'source str) -> Option<AlertView<'source>>`。`str::split_once` 返回分隔符第一次出现前后的原始切片。[标准库 split_once](https://doc.rust-lang.org/std/primitive.str.html#method.split_once)

## 拥有型结果：把文本独立交给调用方

```rust
/// An alert whose fields are owned independently of the input.
#[derive(Debug, PartialEq)]
struct Alert {
    code: String,
    detail: String,
}

/// Parses an alert and creates owned copies of both fields.
fn parse_alert_owned(text: &str) -> Option<Alert> {
    let (code, detail) = text.split_once('|')?;
    Some(Alert {
        code: code.to_owned(),
        detail: detail.to_owned(),
    })
}

/// Retains the parsed alert after its source String has been dropped.
fn main() {
    let alert = {
        let raw = String::from("A18|cache rebuilt");
        parse_alert_owned(&raw).unwrap()
    };
    println!("owned: {} / {}", alert.code, alert.detail);
}
```

输出为 `owned: A18 / cache rebuilt`。`raw` 在内层作用域结束时被销毁；`alert` 仍能使用，因为它持有两份独立的 `String`。这比借用视图增加了字段文本复制和分配，但结果不再受源输入的有效期限制。标准库 [`String::to_owned`](https://doc.rust-lang.org/std/borrow/trait.ToOwned.html) 会为字符串切片创建拥有型文本。

## 选择接口时看调用方的持有需求

| API | 返回值持有什么 | 调用方需要保留什么 | 文本成本 |
| --- | --- | --- | --- |
| `parse_alert_view` | 指向输入的两个切片 | 原始输入要覆盖视图的使用期 | 不复制字段文本、不为字段分配新字符串 |
| `parse_alert_owned` | 两个独立 `String` | 只需保留返回的 `Alert` | 复制字段文本，并为拥有型字段分配存储 |

如果调用方只是立即读取或在同一请求中使用结果，借用视图通常更省分配；如果要把结果放入稍后处理的队列、跨过原输入作用域保存，拥有型结果的边界更直接。不能仅凭“零复制”选 API：检查 owner 由谁持有、结果何时要被使用，再把这个责任写进类型和签名。Rust Book 的结构体引用示例也要求为结构体声明生命周期，并保证实例不超过其引用来源。[含引用的结构体](https://doc.rust-lang.org/book/ch10-03-lifetime-syntax.html#lifetimes-in-struct-definitions)

## 让局部解析结果逃逸会失败

```rust
/// Invalid: the returned view would point into a local String.
fn invalid_alert() -> AlertView<'static> {
    let raw = String::from("A19|temporary");
    parse_alert_view(&raw).unwrap()
}
```

`raw` 在函数返回时销毁。声明 `'static` 不能让这个局部值延长寿命；编译器会拒绝该实现。若调用方确实需要脱离输入保存结果，应改用 `parse_alert_owned`，而不是给借用结构体加一个更长的生命周期名字。

## 分层提示

1. **定位提示**：找出视图结构体中的 `&str` 字段，并标记它们切自哪个输入。
2. **关系提示**：借用实例必须在字段来源有效时读取；拥有型 `Alert` 则保存自己的 `String` 字段。
3. **设计提示**：先问调用方是否要在原输入结束后保留结果，再决定是否复制。
4. **参考方案**：比较 `parse_alert_view` 与 `parse_alert_owned` 的返回类型、调用位置和文本分配点。
