# 验证真实 Markdown 代码与原始实验的测试灵敏度

此前的 `verified-lesson-drills` 已为全部 54 节中文/英文课程提供配套可执行代码；但它**不能证明课程 Markdown 里原样粘贴的每一段 Rust 都可运行**。同理，配套样例的变异测试不能证明学生真正下载的 ZIP 里的公开测试具备相同的故障检测能力。

本轮增加两条互相独立的质量门禁。

## 1. 直接验证 Markdown Rust 代码围栏

运行：

```sh
node scripts/verify-markdown-rust-fences.mjs
```

从下表每节课程的**中英双语 Markdown 正文**逐段提取 `rust` 围栏，要求两种语言中的 Rust 代码逐字节相同，然后直接交给 Rust 1.95.0 / Edition 2024 的 `rustc`：

| 课程 | 验证重点 |
| --- | --- |
| M02-L01 | 六段绑定、类型标注、类型推断和显式转换的可运行源码及部分标准输出 |
| M03-L02 | 两段枚举和匹配代码的可运行源码 |
| M04-L02 | 成功的所有权转移与移动后再次访问的 E0382 |
| M05-L01 | 共享/独占借用的正确示例与 E0596、E0502 |
| M06-L01 | 有效引用与返回局部引用时的 E0106 |
| M07-L01 | 有约束泛型示例与缺少 PartialOrd 时的 E0369 |

脚本在隔离临时目录中直接编译这些**正文原文**：带 `fn main` 的成功示例必须编译并成功执行；其余成功示例至少必须编译；注明为故意失败的示例必须被编译器以对应错误码拒绝。代码示例的数目、顺序、中英一致性改变时测试会失败，须先重新审阅和更新预期结果。

**目前只审核上述六节的完整 Rust 围栏；其余课时和文本/命令行围栏尚未由此脚本逐段编译。** 不应以这项局部验证宣称 54 节的全部 Markdown 代码块都已经执行。

## 2. 对原始 ZIP 的公开测试做盲测

运行：

```sh
python3 scripts/verify-original-zip-blind-tests.py
```

脚本只在系统临时目录中操作，不修改仓库、公开 ZIP 或学生练习。对 M01–M07 七份真实 L05 starter ZIP 分别执行：

1. 安全解压发行的原始 ZIP；
2. 应用已验证的类型修复和最小业务修复，使**原 ZIP 内的原始公开测试**全部通过；
3. 注入一个**仍可编译**的典型错误（折扣比例、秒数乘数、任务查找条件、字符串标点、查找谓词、拥有型字段来源、解析分隔符）；
4. 确认同一个 ZIP 自带的公开测试在行为断言阶段失败，而不是把编译错误误认为发现了业务缺陷；
5. 在下一实验开始前销毁/隔离该目录。

这验证了**七种具体错误**会被公开测试发现，但还不能替代覆盖率分析、模糊测试、更多变异样本或对学生独立实现的全面评价。

## 现有测试之间的区别

- `node scripts/verify-lesson-drills.mjs`：验证课程配套 Rust 正例和预期编译失败。
- `python3 scripts/verify-starter-zips.py`：验证 M01–M07 ZIP 安全、清单、原始故障及修复后公开测试，以及 M01-L06 参考工程。
- `python3 scripts/verify-lesson-mutations.py`：变异配套的参考 Rust 工程，验证参考合同断言是否捕获错误。
- **`python3 scripts/verify-original-zip-blind-tests.py`**：变异学生实际下载的 ZIP 里的修复后源码，测试**原 ZIP 自带断言**是否捕获错误。
- **`node scripts/verify-markdown-rust-fences.mjs`**：直接编译 Markdown 里的原始代码，而不是间接验证另一个配套样例。

后续拓展路线是按课程逐个扩大 Markdown 围栏审核清单，逐步为无 `main` 的片段补全可复现的独立语境，并将更多有价值的错误输入加入公开测试，而非盲目增加纯文字练习。
