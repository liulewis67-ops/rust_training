## 1. 教学原则与毕业能力

课程建设遵循项目的开源、公益定位，面向学习者免费开放，支持社区参与内容纠错、样例完善与教学改进。

以“能完成什么任务”组织知识。先建立理解，再做局部练习，然后放进项目，最后在不同条件下再次验证。概念课负责解释原因，练习负责形成操作能力，项目负责训练取舍与交付。

贯穿主线的六个能力维度及毕业证据：

| 能力 | 基础表现 | 毕业时的可观察证据 |
|---|---|---|
| 语言与类型 | 理解 move、borrow、枚举、trait、Result | 为领域设计类型，解释 API 选择，修复未见过的编译错误 |
| 资源与并发 | 识别共享状态与生命周期 | 有界并发、可取消任务、超时与优雅退出；解释失败行为 |
| 业务建模 | 将需求拆成状态与操作 | 业务不变量落实到类型、事务或检查，并有测试 |
| 数据与接口 | 正确解析、查询、响应 | 参数化 SQL、分页、权限边界、幂等与错误契约 |
| 质量与排障 | 编写测试，阅读诊断和日志 | 定位注入故障、补回归测试、解释性能证据 |
| 交付与维护 | 使用 Cargo、Git、配置与文档 | 可重现构建、部署、迁移、备份恢复和运行手册 |

主要面向有其他语言编程经验的学习者。零基础预备路线独立设置，预计 30–60 小时，覆盖变量、函数、基本算法、终端、文件、Git、HTTP 与 SQL；不计入主线 240 小时。

## 2. 来源、版本与知识映射

来源说明：B 为 [Rust Book 中文版目录](https://kaisery.github.io/trpl-zh-cn/toc.html)，A 为 [Axum 文档](https://docs.rs/axum/latest/axum/)，T 为 [Tokio 官方教程](https://tokio.rs/tokio/tutorial)，S 为 [SQLx 文档](https://docs.rs/sqlx/latest/sqlx/)，O 为本平台原创工程课程。

Rust Book 中文版与 Axum 官方文档构成核心底本，Tokio、SQLx 等官方文档补充具体工程主题。讲解、练习、实验和项目采用原创设计，延伸阅读链接到相应参考章节。

本次 Axum `latest` 显示 0.8.9；这是调研快照，开课应锁定审核后的具体版本。语言采用 Rust 2024 Edition，具体 rustc patch 版本在课程样例验证后确定并写入环境配置，不能只写浮动的 stable。语言版本、Edition、依赖版本是三个不同字段。

| 阶段 | 知识参考 | 原创教学转化 |
|---|---|---|
| S1 工具与基本编程 | B 入门、常见概念、结构体与枚举 | 从终端到测试的一次完整开发循环 |
| S2 所有权与接口 | B 所有权、生命周期 | 数据流图、借用修复与 API 签名决策 |
| S3 表达与建模 | B 集合、泛型、trait、错误处理 | 将业务状态、边界条件与类型连接 |
| S4 工程与同步并发 | B 测试、CLI、智能指针、并发 | 日志工具交付、资源管理和线程问题实验 |
| S5 异步工程 | B 异步章节、T | 受限并发调度器、取消与背压 |
| S6 Axum 与数据 | A、S；T 的任务与状态基础 | 从 API 契约到可测试的持久化服务 |
| S7 安全与可靠性 | A 中间件／错误处理；O | 权限、幂等、事件与可观测性实验 |
| S8 生产交付 | O；相应工具官方文档在制作课包时补齐 | 构建、发布、恢复、性能证据和毕业答辩 |

不同来源的术语或例子不一致时，语言规则以锁定工具链的官方文档与实际编译为准；框架接口以固定版本官方 API 为准。课程不沿用资料中的无条件性能排名或就业宣传。

## 3. 路线规模、节奏与先修关系

完整主线 24 模块，每模块 6 个教学单元：4 节概念／演示课、1 个模块实验、1 次能力检查，共 144 单元。每模块规划 12 道短练习，共 288 道；模块实验、检查和四个项目交付单独计数，不把一道题的多次提交算成更多题。

建议按 24 周、每周约 10–13 小时学习。下表为 240 小时基准分配，已包含短练习、实验、项目和复习；卡点与补基础时可增加至 320 小时。

| 阶段 | 模块 | 基准工时 | 阶段交付 |
|---|---|---:|---|
| S1 开发循环与语言入门 | M01–M03 | 10h | 独立创建、测试并修复一个小程序 |
| S2 所有权与借用设计 | M04–M06 | 28h | 为文本处理库设计合理的参数与返回值 |
| S3 类型、集合与错误 | M07–M09 | 30h | 可复用、有错误模型的业务核心库 |
| S4 工程化与同步并发 | M10–M12 | 30h | P1：日志分析 CLI |
| S5 Tokio 异步工程 | M13–M15 | 32h | P2：受限并发任务执行器 |
| S6 Axum API 与持久化 | M16–M18 | 36h | P3 的接口与数据里程碑 |
| S7 安全、可靠性与观测 | M19–M21 | 32h | P3 完整验收与故障报告 |
| S8 发布、优化与交付 | M22–M24 | 42h | P4：可部署服务与答辩 |
| 合计 | 24 模块 | 240h | 3 个代码项目，其中后端项目有两阶段交付 |

课程可自由预览，建议路径由先修图决定。M07 需要 M03/M05/M06，M10 需要 M08/M09，M13 需要 M09/M12，M16 需要 M13/M14，M18 需要 M09/M16，M19 需要 M17/M18，M24 需要所有项目硬门槛。不要把所有模块简单串成“只依赖前一课”。

## 4. 完整课程表：24 模块、144 教学单元

下列每模块第 1–4 项为概念与演示课，第 5 项为实验，第 6 项为能力检查。编号同时是稳定课程 ID 的基础，例如 M05-L03。

### S1：开发循环与语言入门

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M01 工具链与反馈循环 | ① Rust 解决的问题与路线选择；② rustup、Cargo、Edition 与项目结构；③ build/check/run/test 与诊断阅读；④ Git、格式化、Clippy 与最小测试；⑤ 实验：让一个失败项目重新通过；⑥ 检查：从空目录交付可测试程序 | 能分清编译失败、测试失败、运行失败，提交可重现项目 |
| M02 值、函数与控制流 | ① 变量、可变性、基本类型与推断；② 表达式、语句、函数与返回；③ if、loop、while、for；④ 数组、元组、模式与边界；⑤ 实验：数据单位转换器；⑥ 检查：实现带边界处理的计算函数 | 正常、零值、非法输入有明确行为，不以 panic 替代输入检查 |
| M03 结构化业务数据 | ① struct、字段与方法；② enum 与 match；③ Option 与缺失值；④ 模块、可见性与公共 API 初识；⑤ 实验：内存任务清单；⑥ 检查：任务状态模型与穷尽匹配 | 用枚举表达状态，调用方必须处理缺失值，公共 API 有最小文档 |

阶段检查采用一个陌生的小需求，允许查文档，要求自己完成构建和测试。无需安装环境即可先用 R1 练习；M01 同时教本地环境，后续能转移到真正开发工具。

### S2：所有权与借用设计

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M04 所有权与资源流动 | ① owner、scope 与 Drop；② move 的发生位置；③ Copy、Clone 与成本；④ 函数参数、返回值与部分移动；⑤ 实验：修复文本流水线；⑥ 检查：解释并修复资源移动错误 | 能说明谁拥有数据，选择借用或移动，而非到处增加 clone |
| M05 引用、借用与切片 | ① 共享借用与独占借用；② 借用有效范围与 NLL 直觉；③ String、str、切片与 UTF-8；④ 可变借用冲突与 API 设计；⑤ 实验：零复制文本查询接口；⑥ 检查：陌生借用错误与安全分割 | 借用接口正确，Unicode 边界正确；借用图与代码行为一致 |
| M06 生命周期与返回设计 | ① 引用有效性与生命周期关系；② 函数生命周期标注与省略；③ 带引用结构体、拥有型返回值；④ 'static、边界与常见误区；⑤ 实验：借用配置视图与拥有型配置；⑥ 检查：选择返回引用、String 或 Cow 的适当方案 | 知道标注不会延长实际对象寿命；能解释返回值设计的代价 |

此阶段的可视化使用手工编排、可校验的绑定与作用域图，明确为教学模型，不伪装为任意程序的真实内存调试器。禁止把 move 一律画成“堆数据物理搬家”。

### S3：类型、集合与错误

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M07 Trait 与泛型 | ① 泛型与约束；② trait、impl 与关联类型；③ 静态分发、dyn 与 dyn compatibility；④ From/TryFrom、newtype 与不变量；⑤ 实验：可替换解析器接口；⑥ 检查：选择泛型或 trait object 并验证 | 既有可编译实现，也能解释抽象目的，避免无需求的泛型层次 |
| M08 集合、闭包与迭代 | ① Vec、HashMap 与访问策略；② 闭包捕获与 Fn 系列；③ iter/iter_mut/into_iter；④ map/filter/fold、collect 与惰性；⑤ 实验：日志聚合统计；⑥ 检查：在所有权约束下实现统计 | 正确处理空数据、重复键和借用，解释克隆与分配来源 |
| M09 错误与边界建模 | ① Result、? 与错误传播；② 自定义错误与来源链；③ 库错误和应用错误边界；④ panic、恢复策略与错误信息；⑤ 实验：带错误位置的配置解析；⑥ 检查：为 CLI 与 API 设计不同错误呈现 | 可区分无效输入、缺失资源与内部故障，保留诊断上下文 |

阶段作品为业务核心库：解析、验证、聚合均有测试；错误对调用者有意义。trait 原生 async 与动态分发的关系需单独说明，不把含 async 方法的 trait 直接等同于可用 dyn。

### S4：工程化与同步并发

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M10 可测试的 CLI 工程 | ① Cargo workspace 与模块边界；② 单元／集成／文档测试；③ 参数、配置、文件与标准流；④ 依赖、feature、版本锁与文档；⑤ 实验：P1 日志分析 CLI；⑥ 检查：新格式输入的增量需求 | 命令行契约、退出码、stdout/stderr 正确，业务库可独立测试 |
| M11 智能指针与资源管理 | ① Box 与递归数据；② Rc/Arc 与共享所有权；③ RefCell 与内部可变性；④ Weak、Drop、循环与资源清理；⑤ 实验：修复缓存持有关系；⑥ 检查：针对约束选择最简单的持有方式 | 区分共享所有权和同步；知道内存安全并不自动排除泄漏 |
| M12 线程与同步 | ① 线程、move 闭包与线程结果；② Send/Sync 的约束；③ Mutex/RwLock 与锁范围；④ channel、死锁与有界队列；⑤ 实验：并行日志统计；⑥ 检查：修复锁竞争并给出复现证据 | 无数据丢失，解释锁顺序、共享对象类型约束及串行基线 |

P1 在 M08/M09 积累业务逻辑，M10 集成交付，M12 的并行版本作为扩展，不要求为了练并发强行把小工具复杂化。

### S5：Tokio 异步工程

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M13 Future 与运行时 | ① async/await 与惰性 Future；② task、线程与调度；③ Send/'static 与 spawn；④ 阻塞边界、spawn_blocking 与并发上限；⑤ 实验：诊断阻塞运行时；⑥ 检查：给混合工作负载选择执行方式 | 能解释异步为什么适合等待，不能把 CPU 工作加 async 就视为并行 |
| M14 异步协作与背压 | ① JoinHandle 与任务结果；② mpsc/oneshot；③ select、超时与完成顺序；④ Semaphore、队列与背压；⑤ 实验：有界任务处理流水线；⑥ 检查：高峰负载下不无界排队 | 达到并发上限时有明确策略，任务结果可追踪 |
| M15 取消、退出与验证 | ① 取消安全与中间状态；② drop handle、abort 与协作取消；③ 优雅停机、清理与截止时间；④ 可重复的异步测试；⑤ 实验：P2 任务执行器；⑥ 检查：取消、超时、失败同时出现的故障注入 | 所有任务有终态，关闭过程有时限，不能靠 sleep 猜测试时序 |

Tokio 的教程按任务、共享状态、channel、I/O、select 等展开，本平台在此基础上增加故障场景和交付任务。它的官方说明也区分 I/O 并发与 CPU 并行，课程保留这种边界。[Tokio 教程](https://tokio.rs/tokio/tutorial)

### S6：Axum API 与持久化

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M16 路由、请求与响应 | ① HTTP 契约、方法与状态码；② Router、handler 与启动；③ Path/Query/Json 与提取顺序；④ IntoResponse 与输入拒绝；⑤ 实验：内存任务 API；⑥ 检查：实现一个新资源接口 | 正确与异常请求均有稳定契约，参数解析失败有清晰响应 |
| M17 状态、中间件与边界 | ① State、AppState 与子状态；② 业务错误和服务错误；③ Tower Layer、执行顺序与 tracing；④ 接口分层、路由测试与依赖替身；⑤ 实验：统一错误与请求上下文；⑥ 检查：定位提取器和中间件交互问题 | 状态无隐式全局依赖；明确能返回 HTTP 响应的业务错误与底层服务失败 |
| M18 SQLx 与持久化 | ① SQL、schema、迁移与数据库种子；② 连接池、参数化查询与结果映射；③ 事务、约束、并发更新；④ 分页、索引与离线编译检查；⑤ 实验：P3 持久化任务 API；⑥ 检查：并发修改与事务回滚 | 用数据库约束守住不变量，识别 N+1、连接池耗尽与数据丢失 |

Axum 模块依据官方的[提取器](https://docs.rs/axum/latest/axum/extract/index.html)、[错误处理](https://docs.rs/axum/latest/axum/error_handling/index.html)、[中间件](https://docs.rs/axum/latest/axum/middleware/index.html)文档设计。测试不能只发正确 JSON；必须覆盖缺字段、无效 path、过大 body、未知路由和领域错误。SQLx 教学区分运行时查询 API 和构建期检查宏，依赖锁定后再制作示例。[SQLx 文档](https://docs.rs/sqlx/latest/sqlx/)

### S7：安全、可靠性与观测

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M19 身份、权限与输入边界 | ① 认证与授权；② Session、安全 Cookie、CSRF 与登出；③ 资源归属与角色权限；④ 密钥、密码哈希、输入和日志边界；⑤ 实验：阻止跨用户读取任务；⑥ 检查：权限绕过回归测试 | 资源 ID 可猜也不能越权；采用成熟身份实现，不自创密码协议 |
| M20 可靠接口与事件 | ① 幂等键和重复请求；② 超时、重试和退避；③ SSE/WebSocket 与连接生命周期；④ 后台任务、持久状态和恢复；⑤ 实验：任务状态订阅与重连；⑥ 检查：断线、重复事件与取消竞争 | 区分投递次数与业务效果，重试不重复创建业务对象 |
| M21 观测与故障定位 | ① 结构化日志、trace 与 request ID；② 指标、SLO 与失败分类；③ 连接池、慢查询与队列堆积；④ 最小复现、诊断假设与回归测试；⑤ 实验：注入三种服务故障；⑥ 检查：P3 交付与故障报告 | 根据证据定位问题，敏感数据不进日志，能证明修复有效 |

主线要求掌握 SSE；WebSocket 完整双向协议可作为本模块挑战任务，不让高级通信细节阻塞基础后端毕业。认证课程先教平台统一方案，JWT 作为协议选择讨论，不默认所有网站都需要自建 JWT 系统。

### S8：发布、优化与交付

| 模块 | 六个教学单元 | 必须产出的能力证据 |
|---|---|---|
| M22 构建与发布 | ① release 构建、目标平台与运行镜像；② 环境配置与秘密注入；③ CI、健康检查与滚动更新概念；④ 数据迁移、回滚与兼容窗口；⑤ 实验：自动部署到隔离环境；⑥ 检查：旧版本与新 schema 的失败演练 | 按文档可启动，应用回滚与数据库回退策略分别说明 |

## 5. 每模块的题库构成

每模块 12 道短练习的基线：3 道预测／概念检查、4 道编译或行为修复、3 道函数／接口实现、1 道测试补全、1 道设计解释或代码评审。共 288 道，其中 192 道直接编码任务、72 道理解检查、24 道解释评审。部分高级模块可交换题型，但总表要如实更新。

| 题型 | 例子 | 评测依据 | 避免的问题 |
|---|---|---|---|
| 行为预测 | 判断移动后使用是否能编译 | 固定环境验证＋解释要点 | 只背输出而不理解原因 |
| 编译错误修复 | E0382/E0502/E0597 类型的任务 | 编译、行为测试、必要的人工／静态辅助审核 | 用 clone 或改题目接口绕开学习目标 |
| 实现函数 | 借用文本统计、配置转换 | 公共契约、边界测试、生成数据 | 只通过给出的一个样例 |
| 预期编译失败 | 验证某 API 不允许不合法调用 | 编译失败并符合目标错误类别 | 只要“有任何语法错误”就算通过 |
| 测试补全 | 给幂等创建接口补回归测试 | 测试对正确解通过，对目标错误变体失败 | 写一个永远通过的空测试 |
| 并发排错 | 锁跨 await、无限排队、取消失效 | 受控调度点、事件记录、资源上限 | 靠不稳定的真实时间等待判分 |
| API 行为 | 非法输入与权限请求 | 可信外部 HTTP 驱动器 | 相信学员输出的“全部通过” |
| 设计评审 | 用哪种返回类型、如何拆状态 | 公布评分规程＋人工复核 | 让 AI 的单一意见决定成绩 |

题目元数据至少有：稳定 ID、版本、所属技能、先修、难度、工时、题型、环境、允许编辑范围、公开测试、私有评测引用、分层提示、评分规程、来源和作者。题目难度以试学数据调整，初始作者评级只是估计。

约束如“不能改变函数签名”“不能分配新 String”必须写在题面。无法可靠自动检查的约束由评审确认，不能靠搜索 `clone` 字符串作为唯一判定方式。

## 6. 完整样例课：借用文本而不夺走所有权

课程编号：M05-L03 的代表课包；技能：`borrow.shared`、`text.utf8`、`api.borrowed-output`。此处给出教学与评测规格，不提供应用实现代码。

### 6.1 场景与目标

日志分析器需要获取一行中的第一个字段，同时调用方还要保留整行用于显示。读者需要解释为什么只读操作适合接收 `&str`，并实现返回原始文本切片的接口。

学完后应能：在 String 和字符串字面量上调用同一接口；返回借用切片且不分配新字符串；处理空串和中文；说明返回引用为什么不能活得比输入久。

先修为 M04 和 M05-L01/L02。不会 `Option` 的读者先回 M03，不在本节同时引入未知返回类型。

### 6.2 课中教学脚本

| 环节 | 内容与交互 | 预计时间 |
|---|---|---:|
| 业务问题 | 提取字段后，原始日志还要能继续使用 | 3min |
| 预测 | 展示按值接收 String 的调用，预测后续使用是否可行 | 4min |
| 模型 | 用 owner、借用与切片范围图解释数据关系 | 6min |
| 可运行示例 | 切换 String 与字面量输入，观察相同借用接口 | 5min |
| 错误实验 | 尝试返回局部 String 的引用，读取编译诊断 | 5min |
| 动手任务 | 实现 `first_token(input: &str) -> Option<&str>` | 15–25min |
| 工程讨论 | 为什么这里不接收 `&String`，何时应返回拥有型值 | 5min |
| 迁移检查 | 改为解析由冒号分隔的配置键，使用新的测试数据 | 10min |

### 6.3 练习契约

`first_token` 返回按 Unicode 空白字符划分的第一个非空字段；空输入和全空白输入返回 None；跳过前导空白；大小写与内容保持原样；返回值指向原输入中的区间，不新建拥有型字符串。题目明确选择这一语义，而非让测试暗中决定如何处理空白。

公开用例覆盖空串、单字段、两个字段、前导空格、中文。私有评测类别公开为：制表符／换行／Unicode 空白、重复空白、emoji、长文本和不同来源的字符串。私有具体输入与预期输出不进入浏览器。

测试可以验证行为与借用范围等证据，但“完全无堆分配”另用受控分配观察或人工审查，不承诺仅凭签名就能证明所有实现都不分配。

分层提示：第 1 层提示借用与拥有权的区别；第 2 层提示 UTF-8 不能按任意字节截断；第 3 层指向标准库相关迭代接口；第 4 层给出参考实现及取舍。任何提示都不把隐藏测试写出来。

### 6.4 判定与补救

编译和行为正确得基础通过；能解释返回值关系并独立完成变式题，才记为独立掌握。误把空字符串与 None 混淆，回到契约；发生 UTF-8 切片 panic，回到字符串边界；试图返回局部引用，回到所有权和作用域图。

平台保存代码快照、提示层级、编译诊断、测试结果和迁移检查结果。参考后完成不伪装为独立通过；允许正常继续学习，并在 3–7 天内建议变式复习。

## 7. Axum 样例实验：实现带权限的任务状态变更

实验编号：M19-L05；前置为 M16–M18。目标是在既有任务 API 上添加授权和状态变更，训练接口契约、业务规则与数据一致性。

任务规格：已登录成员可以修改所属项目的任务；旁观者只有读取权限；其他项目成员不可读取或修改；Done 状态回退需要规定角色；不存在、格式错误、未登录、无权限按明确契约响应。题面给出统一“不存在或不可见”策略以避免资源枚举，不能让不同测试要求互相矛盾。

工作区包含可编辑的路由、领域服务和存储模块，公开数据库种子和公开集成测试；认证测试身份由独立测试服务提供，不发真实平台凭据。

验收包括正常更新、非法转换、跨项目访问、并发更新冲突、数据库事务失败、请求过大和日志脱敏。可信测试驱动器在学员程序外发请求，检查响应和隔离测试数据库的最终状态，不依赖学员上传的测试成功标记。

完成后要求提交 300–600 字设计说明：授权放在哪个边界、哪个数据库约束守住状态、为什么选择这一冲突响应、如何定位失败请求。AI 可以建议问题，但最终解释由学习者提供。

## 8. 四个项目交付规格

四次交付共享一条成长路径。P3/P4 为同一服务的两个阶段，不宣传成四个互不相同的完整应用。项目工作量已计入阶段总时数。

### P1：日志分析 CLI（约 12h，S3–S4）

用户需要从文件或标准输入读取日志，按级别、时间范围和关键词过滤，统计数量并输出文本或 JSON。平台提供小规模公开样本及独立的边界数据。

| 里程碑 | 交付 | 验收 |
|---|---|---|
| P1.1 解析核心 | 独立库、解析错误类型、测试 | Unicode、空行、坏行策略明确 |
| P1.2 命令行 | 参数、帮助、stdout/stderr、退出码 | 可组合到管道；错误不会混入正常输出 |
| P1.3 稳定处理 | 流式读取、结果聚合、文档 | 在给定数据规模与内存预算下完成 |
| P1.4 交付 | README、测试、格式检查、示例 | 新环境按说明能构建运行 |

陌生增量需求：增加一个输出字段或新的输入格式。考察 API 和测试是否支持变更，而不只是复制已有代码。

### P2：受限并发任务执行器（约 12h，S5）

处理一批模拟 I/O 任务，支持最大并发、单任务超时、取消、结果聚合和优雅退出。外部服务使用平台隔离的确定性模拟器，避免练习依赖公网稳定性。

| 里程碑 | 交付 | 验收 |
|---|---|---|
| P2.1 生命周期 | queued/running/succeeded/failed/cancelled 状态 | 每个任务都能到达合法终态 |
| P2.2 流控 | 有界队列与并发上限 | 峰值在途任务不超过题目配置 |
| P2.3 失败处理 | 超时、取消、重试分类 | 永久错误不无限重试；取消后有清理 |
| P2.4 停机 | 截止时间、日志、测试报告 | 停止接单并排空或取消已有任务 |

重点故障：丢弃 handle、阻塞 runtime、任务失败被忽略、channel 无界增长。分数不取决于毫秒级跑分，采用行为与资源边界验收。

### P3：团队任务管理 API（约 24h，S6–S7）

实体为用户、项目、成员、任务、任务事件。需求覆盖成员权限、任务 CRUD、过滤分页、状态转换、持久化、重复提交与事件订阅。P3 使用训练身份服务和实验数据库，不接真实生产账户。

| 里程碑 | 交付 | 验收 |
|---|---|---|
| P3.1 契约 | API 说明、内存实现、公开测试 | 状态码与错误结构一致 |
| P3.2 数据 | PostgreSQL schema、迁移、查询与事务 | 约束、回滚和并发修改正确 |
| P3.3 权限 | 用户上下文、成员角色、资源权限测试 | 跨用户／跨项目访问被拒绝 |
| P3.4 可靠性 | 幂等创建、任务事件、SSE 重连 | 重试不重复创建；事件有可追踪 ID |
| P3.5 排障 | tracing、指标、故障报告 | 能定位指定的池耗尽或慢查询故障 |

每次里程碑要求保留已有能力的回归测试。先通过数据库 schema 审核，再把学员程序接入该实验的临时数据库；任何时候不使用平台业务库。

### P4：服务工程交付与毕业答辩（约 30h，S8）

将 P3 演进为可交付的服务：固定构建、最小运行镜像、配置、健康检查、CI、迁移流程、备份恢复和压测说明。平台可提供受控部署演示环境，真实云账户部署作为自选作业，费用不隐藏在课程要求里。

| 里程碑 | 交付 | 验收 |
|---|---|---|
| P4.1 可重现 | 环境说明、锁文件、构建与发布流程 | 新环境能按说明部署 |
| P4.2 可运维 | 日志与指标、告警示例、运行手册 | 指定故障发生时知道如何诊断和处置 |
| P4.3 可恢复 | 迁移、备份、恢复和回退演练记录 | 从备份恢复到隔离环境并核对数据 |
| P4.4 有性能证据 | 固定负载的基准报告与一次改进 | 正确性不回退，写明环境与权衡 |
| P4.5 能独立维护 | 新需求实现、Code Review、答辩 | 能解释设计并现场补测试或修复 |

必须提交代码、测试、API 文档、设计说明、部署与恢复手册、一次故障复盘。个人公开作品页默认不展示私有代码或全部提交历史。

## 9. 考核、评分与真实性

### 9.1 三层评价

形成性评价用于日常学习，不因合理使用提示扣罚。阶段检查验证独立能力，可以查官方文档，但不提供本题答案或 AI 直接补全。毕业项目同时检查运行证据、代码质量与设计解释。

| 项目评分维度 | 权重 | 依据 |
|---|---:|---|
| 功能与契约 | 40 | 公开和受控测试、边界行为 |
| 测试与失败处理 | 20 | 回归测试、错误分类、故障注入表现 |
| 资源、安全与可靠性 | 15 | 权限、并发边界、取消和清理 |
| 设计与可维护性 | 15 | 模块、类型、可读性和改动成本 |
| 交付与解释 | 10 | 文档、重现步骤、答辩 |

建议总分 ≥80，且所有硬门槛通过。越权访问、真实数据破坏、不可构建、关键业务不变量失败不能用其他分数抵消。不同项目只应用与其有关的硬门槛；P1 不凭空要求 Web 权限系统。

### 9.2 证据与复核

基础库练习的内部测试用于学习反馈，不能完全抵御恶意代码伪造结果。正式能力检查优先使用外部进程／协议驱动器、服务外部 HTTP 测试、不可由学员修改的监督进程和人工复核。隐藏测试不是系统安全秘密，也不能仅凭“没发到前端”就认为绝对保密。

证据保存题目版本、工具链、源代码哈希、运行环境版本、评测器版本、辅助程度、结果和审核记录。平台不能只凭一张绿色成功截图发证。

抄袭相似度可用于提示复核，不能自动判罚。复核以解释代码、陌生变式与修复能力为主。学员能提交异议；题目有误时修正、重评并说明受影响范围。

### 9.3 复习策略

诊断按错误性质分流：语法与工具、所有权、类型约束、错误传播、业务边界、并发时序、环境故障。每次优先推荐一项最接近原因的知识点。

不要把一次错误映射成“你不懂整个并发模块”。学习者可以查看推断依据、忽略建议或直接挑战新题。断网、排队和运行器故障不进入技能薄弱统计。

## 11. 内容生产规范与质量门槛

每个课程包包含目标、正文、图示说明、示例、题目、公开测试、私有评测引用、参考解、分层提示、术语、先修、来源、版权状态和环境配置。正文中的代码标记为以下三类之一：完整可运行；教学片段；预期编译失败。

发布流程：作者原创 → 技术审核 → 正反例验证 → 小范围试学 → 修订 → 固定版本发布。运行示例必须使用对应工具链自动校验；片段不能显示误导性的“运行”按钮；失败示例校验错误类别和关键代码范围，不死锁在易变的整段诊断文案上。

题目测试必须验证至少一个正确实现、几个有代表性的错误实现，以及边界条件。固定时间的并发测试要尽量改为可控时钟、事件或确定性调度点。对性能要求，先写明机器、负载和容差，再决定能否用于评分。

原创课程按读者反馈维护：每次修改有内容 diff、版本说明、回归运行和受影响技能列表。来源网页变化只触发复核，不自动覆盖已经发布的课程与成绩。
