# 课程内容结构与阅读体验规范

## 目标

公开课程不应仅仅是连续的技术文章。每节课应让学习者迅速回答：为什么学、学完能做什么、需要什么基础、关键机制是什么、如何自己验证。保留必要的技术深度与完整代码，不为了缩短篇幅删去边界条件。

## 推荐的单节课程结构

1. **学习目标**（3–4 条可验证的行为，不写“了解”之类模糊表述）。
2. **先修与场景**（一个具体问题，前置知识和边界）。
3. **核心知识点**（通常 2–4 个二级标题；每节说明“问题 → 规则 → 最小 Rust 代码 → 结果与原因 → 常见错误”）。
4. **Java / Go 对比**（仅当对比有助于理解时加入；区分 GC、所有权、调用约定及内存布局，避免不严谨的“一定更快”）。
5. **检验理解**（预测代码运行/编译结果，并说明原因；提示和参考答案保持折叠）。
6. **本地练习**（2–3 个递进任务，明确输入/输出/验收命令；模块综合课可以更多）。
7. **小结和来源**（三条核心结论与官方文档链接）。

模块实验与综合检查允许专门组织“目标 → 项目契约 → 任务拆解 → 验收 → 提示 → 参考方案”，不强行按概念课模版写作。

## 内容编辑原则

- 一个二级标题对应一个可辨别的教学任务；过大的标题拆成多个概念，但不按固定字符数机械切分。
- 段落只表达一个因果链；代码紧跟解释，介绍前先给出要预测或解决的问题。
- 复杂概念先写结论，再展示反例及修复，最后对比工程取舍。
- 明确区别 Rust 编译期错误、运行时 panic、业务错误；代码片段标注是否预计编译通过。
- 练习先给题目与验收规则；提示与答案继续使用现有 `## 分层提示`/`## 参考答案` 折叠语义。
- 任何重构不得改变公开课程的稳定 ID、源码链接、Rust 语义与原本的知识覆盖。
- 对中英双语保持标题层级一致，中文课程尚未完全翻译时遵循网站已有提示。

## 阅读界面

阅读页根据原 Markdown H2 标题自动形成学习导航与知识点序号，区分准备信息、核心概念、应用练习与参考资料。此实现不会使用固定字符分块，也不重新生成 Markdown 内容。原有深链接和重复标题的锚点继续工作。

## 后续逐课编辑的检查项

- [ ] 每节有明确的目标、先修条件和问题情境。
- [ ] 每个核心知识点都包含可运行或明确标为不可编译的代码。
- [ ] 每节至少有一个预测/纠错检查点，以及练习验收办法。
- [ ] 教学结论和代码与锁定 Rust 版本一致。
- [ ] 没有与练习重叠、过早剧透的正文答案。
- [ ] 标题规范在中文和已翻译的英文课程中均可识别。
- [ ] 在桌面和手机上检查导航、横向代码滚动及键盘焦点。
- [ ] 执行 `pnpm check:frontend` 与 `pnpm content:validate-public`。
