# 后端开发规范

版本：v1.0｜日期：2026-10-11｜适用范围：业务 API、协调器、可信运行控制服务、后端测试及开发脚本

关联：[技术方案](./technical-design.md) · [前端开发规范](./frontend-development-standards.md) · [实施路线图](./implementation-plan.md)

## 1. 执行原则与技术基线

本文作为后续开发和代码评审的执行标准。“必须／禁止”为验收要求，“建议”为默认选择，可在任务记录中说明调整原因。所有新增与修改函数必须满足注释要求；既有代码随模块开发逐步补齐。

后端沿用技术方案：Rust＋Axum＋Tokio 模块化单体，PostgreSQL＋SQLx，S3 兼容对象存储，持久任务表与租约协调。业务服务与不可信代码运行节点必须隔离。

当前工作区尚无 Cargo 工程或后端实现。以下目录、检查和契约是开发约定，不能视为已建成的能力。初始化时通过兼容性样例固定 Rust 工具链、Edition、MSRV、依赖组合和镜像 digest，提交 `Cargo.lock` 与工具链配置；不把某个文档的 latest 版本当作已验证组合。

本仓库的日常开发环境为 Windows 原生环境，命令示例使用 PowerShell；不要求 WSL。当前本地工作不启动 Linux 容器或进行 Linux 执行验证；Linux 执行环境属于后续目标，不能把配置审查当作验证证据。CI 使用 Linux runner 是自动化验证环境，不改变本地 Windows 开发方式。

## 2. 工程组织与模块边界

建议在 `backend/` 建立 Cargo workspace，前端继续保留现有根目录结构。按实际交付创建目录，不提前生成空框架：

```text
backend/
  Cargo.toml
  Cargo.lock
  rust-toolchain.toml
  crates/
    app/                # 业务模块、HTTP 接入、持久化适配及 API 启动入口
      src/
        modules/        # identity、catalog、learning、assessment 等
        http/           # 路由组合、会话、中间件、错误映射
        infrastructure/ # 数据库、对象存储及其他外部适配
      tests/            # API 与跨模块集成测试
    coordinator/        # 租约调度、失联恢复、清理协调
    runner/             # 独立部署的可信监督进程
    execution-protocol/ # 最小运行协议，不承载业务数据库模型
  migrations/           # 按执行顺序版本化的数据库迁移
```

- 以 Identity、Catalog、Learning、Assessment、Workspace、Execution、Projects、Authoring 划分业务职责。HTTP handler 负责提取、校验、调用用例和映射响应；业务规则不散落在路由和 SQL 拼接中。
- 依赖方向为 HTTP／基础设施适配到应用与领域规则。领域类型不依赖 Axum 提取器或数据库连接；在模块内部用小接口隔离真正需要替换的外部能力，不强制每个函数配一套 trait。
- 数据库行模型、API DTO、领域模型分别承担持久化、传输和业务职责，不直接把完整数据库行序列化给客户端。
- 模块只公开必要接口；跨模块通过应用接口协作，禁止任意修改另一模块拥有的表。
- runner 不依赖业务 API crate，不持有平台数据库或对象存储管理凭据；共享协议只包含执行所需的有限字段。

## 3. Rust 编码与类型

- 模块、函数、变量使用 `snake_case`；类型与 trait 使用 `PascalCase`；常量使用 `UPPER_SNAKE_CASE`。名称表达领域含义，避免 `data`、`manager` 等泛化命名。
- 用新类型区分易混淆的用户、任务、快照及版本 ID；状态与动作使用枚举，禁止依赖任意字符串和布尔组合表达合法状态。
- 默认借用只读输入，按实际所有权传递数据；不能为消除编译错误盲目 `clone`，也不为减少一次小复制引入不必要的生命周期复杂度。
- 业务失败返回有语义的 `Result`，`Option` 只表示正常缺省。禁止把数据库错误、鉴权失败或资源超限伪装成空结果或成功。
- 生产请求路径禁止对外部输入使用 `unwrap`、`expect`、断言或索引 panic。内部不变量如需 panic，必须解释前提和影响；测试中的 `expect` 应给出失败原因。
- 生产业务代码默认禁止自写 `unsafe`；确有底层需求时隔离到最小模块，写明安全契约并单独评审。
- 以 rustfmt 为格式基线；lint 例外限定到最小范围并写明理由，禁止整 crate 屏蔽警告掩盖问题。

## 4. 注释规范（强制）

### 4.1 每个函数必须有注释

覆盖 `pub` 与私有函数、`async fn`、`main`、方法、trait 声明与实现方法、测试函数、测试辅助函数及闭包。可见性低或代码短不构成免注释理由。

- 命名函数和方法统一使用紧邻声明的 `///` 文档注释；模块或 crate 的职责使用 `//!`。公开类型和关键字段也需说明业务含义。这与 [rustdoc 文档形式](https://doc.rust-lang.org/rustdoc/how-to-write-documentation.html)一致，本项目额外要求私有函数也写注释。
- 首句说明用途；按需补充参数的单位、范围、权限前提，返回语义、副作用、事务边界、幂等性、取消及重试约束。
- 返回 `Result` 的函数通过 `# Errors` 说明可预期失败。存在可达 panic 时写 `# Panics`；`unsafe fn` 必须写 `# Safety` 并在危险操作处写 `// SAFETY:` 说明成立依据。
- trait 声明说明契约，实现方法说明本实现的额外行为或引用对应契约，不能只留“实现方法”。
- 闭包在表达式前或函数体首行写 `//` 说明职责；复杂闭包拆成有文档注释的函数。测试注释说明场景与预期结果。
- 默认中文注释，保留英文 API 名称；注释随行为一起修改，不保留失效描述。简单函数一句话即可，不要求堆砌无内容的章节。

### 4.2 复杂实现必须有行内注释

行内注释放在函数体内、紧邻对应语句，可独占上一行，重点解释原因、不变量和失败后果。以下情况必须写明：

- 锁顺序、锁范围、跨任务通信、取消安全和资源释放。
- 事务隔离、条件更新、唯一约束、幂等键、租约与 fencing token。
- 状态迁移、终态竞争、重复回传、退避重试和失败补偿。
- 路径归一化、白名单、受限网络、凭据边界和输出截断。
- 非直观算法、性能优化、兼容处理与外部系统限制。

禁止用注释代替可理解的命名与拆分；禁止逐句翻译显然的语法。临时方案使用 `TODO(任务ID): 原因与移除条件`，不留大段注释掉的旧代码。

### 4.3 示例

以下为注释风格示例，仅表达租约代次递增规则，不构成完整的任务领取实现：

```rust
/// 租约代次无法继续递增时返回的错误。
#[derive(Debug, PartialEq, Eq)]
pub enum LeaseError {
    GenerationExhausted,
}

/// 计算下一次领取任务应使用的租约代次，不修改持久状态。
///
/// 调用方必须在领取事务内原子写入新代次和租约信息。
///
/// # Errors
/// 当前代次达到上限时返回 `LeaseError::GenerationExhausted`。
pub fn next_generation(current: u64) -> Result<u64, LeaseError> {
    // 禁止回绕复用旧代次，否则过期 worker 的回传可能重新通过校验。
    current.checked_add(1).ok_or(LeaseError::GenerationExhausted)
}

#[cfg(test)]
mod tests {
    use super::{next_generation, LeaseError};

    /// 代次耗尽时必须失败，防止旧 worker 的代次被重新使用。
    #[test]
    fn rejects_generation_overflow() {
        assert_eq!(
            next_generation(u64::MAX),
            Err(LeaseError::GenerationExhausted),
        );
    }
}
```

## 5. HTTP 与共享契约

- 接口统一在 `/api/v1` 下；OpenAPI 为契约来源，声明参数、鉴权、成功与错误响应、限额和幂等行为。接口变更、生成类型和调用端适配在同一小阶段交付。
- JSON 字段使用 `snake_case`，枚举值使用稳定的 `snake_case` 字符串；ID 按不透明字符串传输。时间使用 UTC RFC 3339 字符串，持续时间字段带单位后缀，如 `timeout_ms`。
- 成功响应使用明确资源 DTO；列表定义分页、稳定排序与数量上限。数据库模型或内部凭据不得直接返回。
- 创建异步任务返回 `202` 和任务 ID；接受请求不代表执行成功。草稿 revision 不符返回 `409`，禁止覆盖已有版本。
- 不兼容字段或行为变更需版本化并说明迁移；新增字段也要验证旧客户端行为，禁止无记录改写已有枚举语义。

统一错误响应约定如下，`field_errors` 为可选字段，错误消息用于展示，客户端判断使用稳定的 `code`：

```json
{
  "code": "workspace_revision_conflict",
  "message": "工作区已在其他位置更新，请先比较版本。",
  "request_id": "req_example",
  "retryable": false,
  "field_errors": [{ "field": "revision", "code": "stale_revision" }]
}
```

| 场景 | HTTP 状态 | 处理约定 |
|---|---:|---|
| 无效格式或字段约束失败 | 400 | 返回稳定字段错误，不泄漏内部校验对象 |
| 无有效会话 | 401 | 引导重新认证 |
| 已认证但无操作权限 | 403 | 不泄漏无权查看的对象信息 |
| 资源不存在或对调用者不可见 | 404 | 统一响应，避免对象枚举 |
| revision／幂等请求体冲突 | 409 | 客户端调整后再发起操作 |
| 请求体超过限制 | 413 | 明确输入限制 |
| 超过速率或配额 | 429 | 按策略提供重试信息 |
| 内部故障／暂时不可用 | 500／503 | 脱敏响应，服务端保留关联诊断 |

框架提取器、反向代理与业务层错误需验证一致性；客户端仍应容忍网关返回非 JSON 故障响应。不得用 `200` 包装失败，也不能直接返回 SQL、堆栈、宿主路径或凭据。

## 6. 数据库、迁移与事务

- SQL 使用绑定参数；动态排序、列名和操作符通过白名单选择，禁止拼接用户输入。查询设置分页和必要超时，避免无界扫描与 N＋1 查询。
- 主外键、唯一约束、非空和检查约束表达数据不变量；对象授权在查询或业务条件中落实，不能依赖前端传入 owner ID。
- 事务由用例明确控制，覆盖需要原子性的记录。禁止在事务持锁期间等待编译、运行、长轮询或不受控外部请求。
- 已应用迁移不可改写；新增迁移需验证新建库与旧版本升级。破坏性迁移先说明兼容窗口、数据保护、失败恢复和回退策略。
- SQLx 查询采用编译期检查时，在 CI 提供验证数据库或维护匹配的离线元数据；不能把无数据库导致的跳过当作查询验证通过。
- 发布后的课程、环境、评分规则与快照按不可变版本引用；历史成绩不依赖可变的 `latest`。
- 时间以 UTC 保存，学习日由用户时区计算；源码与产物按对象存储策略管理，不随意塞入日志或公共缓存。

## 7. 异步、任务与资源生命周期

- Tokio 请求任务中禁止同步阻塞 I/O、线程睡眠和长时间 CPU 计算。可信阻塞工作进入有并发上限的专用执行边界；学员代码始终交给独立沙箱。
- `spawn_blocking` 任务开始执行后不能通过普通 abort 强制停止，因此超时包装不能替代底层停止与资源回收设计。参见 [Tokio 官方说明](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html)。
- 共享状态优先不可变；确需锁时明确锁顺序与持有范围。不得持同步锁跨 `.await`；需要跨等待维护串行访问时专门设计异步锁或消息驱动所有者，并记录原因。
- 通道、任务数、连接池和缓冲区必须有上限；达到容量时有可观测的背压或拒绝行为，禁止无限 `spawn`。
- 后台任务必须有所有者、退出信号和结果处理；进程退出时停止领取、处理在途任务、释放资源并记录未完成清理。
- 取消要覆盖工作任务、子进程、数据库实验和网络资源；仅停止等待 Future 不等于外部操作被撤销。

## 8. 执行状态、幂等与可信成绩

- 状态机遵循技术方案：`queued → preparing → compiling → running → grading → terminal`，具体终态使用约定枚举。跳过阶段必须与动作匹配，终态只能原子确定一次。
- `cancel_requested_at` 与实际取消终态分开保存；取消和正常完成竞争时通过条件更新决定结果。
- 创建任务、队列记录及初始状态事件在同一事务落库；外部消息系统以后接入时使用可靠发布机制，不能先提交业务再裸发消息。
- 幂等键至少按用户与操作隔离，保存请求摘要和结果；相同键不同输入返回冲突。键有效期和过期行为写入契约。
- 领取采用短事务、租约、心跳与递增 generation；所有回传校验任务、有效租约和 generation。不得接受旧 worker 覆盖新一轮结果。
- 至少一次执行通过唯一约束和终态更新避免重复扣额、重复计分；不能仅靠内存标记或假设队列只投递一次。
- 基础设施故障可按上限重试；用户编译失败、测试失败不自动重试。清理失败进入隔离与重试流程，资源不得直接分配给下一用户。
- 正式成绩只接受可信监督进程和评测驱动器的受权结果；客户端事件、学员 stdout 和可修改测试输出都不能直接构成权威成绩。
- SSE 事件包含任务 ID、递增序号和明确类型；定义保留窗口、断点重放及过期恢复行为，流和状态查询均进行对象授权。

## 9. 身份、安全与执行隔离

- 沿用 OIDC＋服务端 Session 方案。所有对象访问都验证当前用户权限，包括快照、产物、事件流、预览和管理接口。
- Cookie、CSRF／Origin、会话撤销与最小角色权限按技术方案实施；控制平面凭据短期、限定任务和动作，不放入学员环境。
- 入参限制大小、文件数、展开总量、路径深度、输出量和运行时间；拒绝目录穿越、绝对路径和可逃逸链接，校验归一化后的真实访问边界。
- 执行请求只允许固定动作、版本化环境与受控参数，禁止任意 shell、镜像、挂载和环境变量字典。
- 编译和执行同等隔离；普通容器不作为公网恶意代码的唯一边界。禁止业务进程或开发机直接执行上传代码，运行验证使用专用 Linux 隔离环境。
- 隐藏测试、参考解私有部分和评分凭据不得进入公开课程包或学员可读目录；公开发布使用明确文件白名单。
- 默认拒绝沙箱公网和控制面访问；R3 只开放本实验必需的网络与数据库。输出和回传仍作为不可信数据校验。

## 10. 配置、日志与可观测性

- 配置启动时解析为强类型并校验；缺少必需项立即以脱敏错误失败。仓库只保存无秘密的配置样例，生产密钥经受控机制注入。
- 使用结构化日志，贯穿 `request_id`、`run_id`、`attempt_id` 和环境版本；记录关键状态迁移和失败类别。
- 默认不记录完整源码、stdin、原始请求体、会话或凭据；错误保留内部原因链，在 HTTP 边界统一脱敏。
- 度量排队、执行、超时、资源超限、租约重领与清理失败；学生编译错误与平台基础设施错误分开计数。
- 指标标签不包含用户 ID、任务 ID 等高基数字段；这些信息放在受控日志或追踪中。
- 区分进程存活与服务就绪；依赖不可用时不伪装就绪。备份必须验证恢复，发布记录迁移顺序与回退条件。

## 11. 验证与提交门槛

Cargo workspace 建立后，在 `backend/` 下执行以下基线命令；当前未创建工程，不能把这些命令标为已通过：

```powershell
cargo fmt --all -- --check
cargo check --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo doc --workspace --no-deps --locked
```

固定工具链需包含 rustfmt、Clippy。CI 按支持的平台和 feature 组合建立矩阵，不盲目启用互斥的全部 features；文档检查配置为警告失败。集成测试所需 PostgreSQL、对象存储和隔离运行环境由任务说明明确，缺少环境的检查标记未运行，不能静默通过。

测试以行为和故障边界为目标：纯领域规则用单元测试；数据库约束与事务使用真实 PostgreSQL 集成测试；接口验证鉴权、输入、错误契约；调度验证重复领取、租约过期、晚到结果、取消竞争与重启恢复；隔离测试验证资源耗尽、越权和清理，且只在专用环境运行。

公开可运行文档样例纳入 doc test；预期失败教学代码显式标记并按课包流程验证。`missing_docs` 等 lint 不能覆盖所有私有函数和闭包，仍需人工检查注释完整性与准确性。

每次提交前检查：

- [ ] 所有新增或修改函数都有有效注释，复杂并发、事务与状态逻辑有行内说明。
- [ ] 模块边界、输入约束、对象授权、错误响应与 OpenAPI 一致。
- [ ] 迁移、幂等、取消、重试和资源清理在相关功能首次交付时有效。
- [ ] 相关格式、编译、lint、测试及文档检查通过，未运行项和原因已明确记录。
- [ ] 验证记录包含环境、命令、输入、预期与实测；秘密和私有评测内容未进入公开产物。
- [ ] 更新契约、配置说明和任务台账，按实施路线图保持一个小阶段一次提交。
