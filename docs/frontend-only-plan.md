# rust.path：纯前端开源学习站改版方案

版本：v2.7｜日期：2026-10-17｜状态：纯前端站点已上线，M01–M04 已发布

本方案是当前产品范围、架构和实施顺序的入口。与旧 PRD、技术设计、课程设计、I01–I13 台账冲突时，以本文为准。旧文档和验收记录保留为历史，不把取消的任务改记为完成。纯前端基础站点已在 GitHub Pages 上线；阶段状态、课程发布进度和未完成的线上验收见[实施记录](./frontend-implementation.md)。未经构建、测试或线上检查的行为不标记为已验证。

## 1. 产品定位

建设免费、开源、无需注册的 Rust 工程学习网站，源码和教学内容通过 GitHub 协作，网站以静态文件形式托管到 GitHub Pages。

网站负责课程组织、阅读、练习说明、提示、参考解、项目材料和轻量学习记录；学习者在自己的电脑上使用 Rust 工具链完成编码与项目实践。站点的价值集中在课程质量、解释清晰度和工程训练的连贯性。

保留 Rust 基础 → CLI → 并发与异步 → Axum → 数据与安全 → 交付与维护的学习主线。网站改为纯前端不意味着删除教学内容中的后端、数据库和部署实践。

## 3. 使用流程与页面

主要流程：打开网站 → 选择路线／模块 → 阅读课程 → 做理解题 → 下载或复制练习 → 在本地运行 → 对照测试与参考解 → 可选标记完成 → 下一课。

主导航保留：首页、学习路线、搜索、复习、学习进度、GitHub。移除注册、登录、个人中心、云同步状态和运行队列入口。学习进度页是当前浏览器的学习记录，不包装成账户档案。

课程页统一包含：

1. 学习目标、先修知识、适用工具链版本。
2. 正文、正常示例、常见错误与原因。
3. 理解题与解析、编码练习与分层提示。
4. 本地实践说明：文件结构、工作目录、运行命令、预期结果。
5. 起始项目下载或仓库路径，以及参考实现、自查清单。
6. 上一课／下一课、已阅读／自报完成、内容纠错入口。

“开始练习”定位到本地实践说明；“下载模板”“复制命令”“查看参考解”表达真实行为。删除“运行”“提交评测”“平台已验证”等与实际能力不符的按钮或文案。参考解默认折叠只是教学安排，不是保密措施。

## 4. 课程资产与验收语义

保留 S1–S8、M01–M24 和既有课程 ID。144 个教学单元、288 道短练习、24 个实验及 P1–P4 交付节点继续作为长期课程规划；P3/P4 可以沿用同一后端项目逐步交付，不要求为了数量新增项目。数量不代表已发布库存，也不作为首次发布的硬门槛。

每模块原有的 4 节概念课、1 节实验、1 次独立检查结构可保留。独立检查改为“综合自测／迁移练习”，公开题目与验收规程。学习者可先独立完成再对照答案，网站不声称能核实其独立性。

已发布静态课包中的答案、提示和自测材料均按公开内容处理；运行时 JSON 不携带私有评测引用。公开站点只提供可见题面和参考材料，不模拟隐藏评分或平台提交。

每节编程课程至少交付：目标、正文、起始代码、明确工作目录和命令、正常／预期失败结果、提示、参考解及来源。复杂实验明确 Windows/Linux、数据库或容器前提。服务部署课仍须验证真实服务行为，不能因站点取消后端就把进程内模型当成已完成的部署实验。

对 `content/drafts/`、`public/`、`solutions/`、`private-assessment/` 做逐项内容盘点：

- 已完成的正文、练习、starter、参考解和验证记录优先复用。
- 原私有测试和评分规程中有教学价值的部分整理成公开自查材料；不再设计防作弊与受控评分。
- 草稿、作者备注与正式课程分开是内容质量管理，不再是答案安全边界；公开仓库中的文件均按可被读者查看对待。
- 内容台账分为草稿、待核验、可发布、已发布，记录适用环境与验证证据；旧作者侧验证不能自动等同于学习者完整流程验证。
- 发布清单现已统一控制公开 JSON 课包与 Markdown 课节；运行中的课程目录和搜索不读取 `content/drafts/`。当前 M01–M04 每个模块的六节均进入清单。
- 未完成模块可以展示大纲和待发布状态，但不能出现空课程、失效下载或虚假的“已完成”标志。

阅读完成、前端小测正确、学习者自报本地验证是不同记录。取消平台能力认证，不用阅读次数推断工程能力。发布质量以可读、可复现、可下载、链接有效为准，不再依赖在线运行成功率、付费／账户指标或后台分析系统。

## 5. 纯前端技术方案

继续使用现有 React 18、TypeScript、Vite、现有样式和功能目录，不引入新框架，不搭建替代后端、Serverless、BaaS 或云数据库。

```text
仓库中的课程、练习和资源
        ↓ 内容检查／构建
React + 静态课程数据 + 下载文件 → dist/ → GitHub Pages
        ↓ 浏览器
阅读／搜索／自测／导航 ↔ 内存状态 ↔ localStorage（可失败）

下载的 Rust 项目 → 学习者自己的电脑 → 本地运行与测试
```

### 5.1 路由与子路径

首版统一采用 Hash 路由，例如 `/<repo>/#/courses/m01/l01`、`/<repo>/#/progress`。沿用现有路由意图与课程 ID，改造 `src/app/router.ts`，无需仅为此新增路由库。章节锚点约定使用查询参数或路由内片段，并验证回到指定章节。

Vite 的 `base` 使用实际部署仓库路径 `/<repo>/`；用户站点或自定义域根路径使用 `/`。图片、下载、搜索资源与内部链接统一经过 base-aware 的路径构造。官方配置依据见 [Vite GitHub Pages 部署说明](https://vite.dev/guide/static-deploy.html#github-pages)。

当前 `scripts/course-page-renderer.mjs` 会生成独立静态课程 HTML。首版将其退出默认站点构建，统一到一个 React 阅读入口，消除双套课程视图和根路径假设；保留可复用的内容校验逻辑。旧链接如需兼容，按已存在的路径清单生成小型静态跳转页，跳转到规范 Hash 地址；未知路径显示 404 和返回目录入口。搜索引擎逐课索引与无 JavaScript 阅读后续按需求评估，不伪称 Hash 方案具备完整静态预渲染能力。

### 5.2 学习记录

默认尽力保存：最近阅读课程、已读课程 ID、手动完成状态、每题最近一次回答及复习标记、主题偏好。首版不保存完整代码工程、运行日志、无限增长的提交历史或长篇笔记。

复用 `browserStorage.ts` 的异常处理和现有可用校验；将 `useProgress.ts` 从账户／云端同步中解耦。状态先更新到内存，再尝试持久化，不能因存储失败阻止答题或导航。

- 格式带 `schemaVersion`，课程引用使用稳定 ID；记录有数量和文本长度上限。
- 捕获读取、JSON 解析和写入异常；损坏、不支持的版本、容量不足或浏览器禁用存储均降级为内存模式。
- 降级时只显示简短提示：“当前记录不会在关闭页面后保留。”不反复弹窗。
- 同源已有匿名 v2 数据能安全兼容时复用，旧 v1 可进行一次轻量转换；不自动合并账户分区，也不为此增加云迁移系统。
- 不覆盖无法识别的历史数据。提供“清空本站学习记录”，只删除本站明确拥有的 key，不调用 `localStorage.clear()`。
- 新部署域名无法自动读取原域名数据，接受从空记录开始；清理浏览器或换设备后记录消失属于允许行为。
- 同一 `github.io` origin 的多个项目按应用／部署路径命名空间隔离 key。localStorage 按 origin 区分，而非按 URL 路径隔离，依据见 [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。

无需账号 ID、同步队列、幂等事件、远端版本号、冲突合并或草稿 IndexedDB。已有草稿不主动清除，但不再承诺由新版提供代码编辑与恢复入口。

### 5.3 内容加载与缓存

课程目录和搜索摘要保持轻量；正文按课节延迟加载，避免把全部课文装进首屏。当前发布清单同时提供已发布课节的 ID 与标题，目录只读取这些元数据；课文通过 Vite 懒加载模块在阅读时加载，搜索页首次查询时再加载已发布正文。发布清单仅引用审核后的内容，下载资源在构建时核对存在性和路径。

删除默认 Service Worker 注册和全站预缓存生成。若原部署已有安装用户，在原脚本 URL 放置一次性退役 worker，注销对应注册并清理本站已知 cache 前缀；只停止注册不足以移除旧 worker。不得注销同 origin 其他项目的 worker 或删除其缓存。新 Pages 地址不依赖旧域迁移成功。

## 7. GitHub Pages 与开源维护

GitHub Pages 托管构建后的 HTML、CSS、JavaScript 和静态资源，符合此方案的部署方式，见 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

部署流程：PR 检查 → 合并到默认分支 → 安装锁定依赖 → 检查前端与待发布内容 → 构建 `dist/` → 上传 Pages artifact → 部署。PR 不发布到正式站；发布失败保留上一次成功版本。使用仓库实际默认分支和 Pages URL，不写死当前本地目录名作为远程仓库名。

前端开发与构建只需要 Node/pnpm。作者维护 Rust 样例时才需要 Rust 工具链；CI 可使用独立课程检查 job 验证变更样例，相关课程发布必须通过适用检查。网页不执行读者提交的代码，站点发布不再依赖后台服务、数据库或运行器。课程的真实集成检查另设明确环境，未执行时不得记录为通过。

已为软件代码采用 MIT License，为原创课程与文档内容采用 CC BY 4.0，并新增贡献指南；第三方材料不由仓库许可覆盖。M01–M03 的已发布内容见[首批来源审查](./frontend-source-review-m01-m03.md)，M04 已发布内容见[M04 来源审查](./frontend-source-review-m04.md)；未审查的草稿不得进入正式发布目录。构建工具与应用运行依赖分开声明，站点随包附上实际进入产物的第三方许可文本。课程纠错通过 GitHub Issues 或 Pull Request 处理。
