# Rust 课程结构性重构：贯穿式学习主线

## 核心结论

当前发布范围是 M01–M09，共 54 节课（每模块 6 节）。现有内容已包含学习目标、先修、实例、练习、模块实验与独立检查，但各课的例子和概念不一定形成读者可感知的累积链。不能继续用“每节增加几个知识点”来修补。

**统一驱动问题：如何从零开发一个可验证、资源边界明确、输入失败可诊断的 Rust 日志与配置处理核心？** 从头到尾逐步增强同一工程能力；单课可以采用最小独立示例，但必须说明该例怎样迁移到主线工程。当前不是一个已交付的跨模块 starter，不能在页面宣称有可下载的完整项目。

## 九个模块的因果顺序

| 阶段 | 先前已能做什么 | 新出现的问题 | 本模块引入的能力 | 验收证据 |
| --- | --- | --- | --- | --- |
| M01 构建与验证 | 有其他语言开发经验 | 如何保证本地修复可信、可复现 | rustup、Cargo、fmt、Clippy、tests | 可复现构建与最小测试 |
| M02 类型与计算 | 能跑和测一个 CLI | 原始输入、溢出与边界仍含糊 | 类型、表达式、函数、控制流 | 数据单位转换器的边界测试 |
| M03 领域建模 | 能实现数值计算 | 裸参数不能准确表达状态 | struct、enum、Option、模块 | 内存任务清单的合法状态 |
| M04 所有权 | 有领域模型 | 值跨函数后谁负责资源 | owner、scope、move、clone、Drop | 文本流水线的所有权审计 |
| M05 借用 | 理解 move 与复制 | 只读时不应强迫移动或克隆 | &T、&mut T、切片、UTF-8 | 零复制文本查询及借用冲突修复 |
| M06 生命周期 | 会在局部作用域借用 | 返回引用或存入结构体是否安全 | 生命周期关系、拥有型结果 | 配置视图与安全返回选择 |
| M07 泛型与 trait | 能设计安全的具体函数 | 多种解析策略代码重复 | 泛型约束、trait、分发和转换 | 可替换解析器及策略契约 |
| M08 集合与迭代 | 能处理单个类型和解析器 | 如何对大量日志聚合并确定输出 | Vec、HashMap、闭包、迭代器 | 重复键、排序及统计测试 |
| M09 错误边界 | 正常输入下能稳定产出 | 配置或解析失败时如何解释 | Result、?、错误链、应用边界 | 带错误位置的配置解析器 |

**课程进阶依赖（不是单纯目录）：**

```text
M01 可复现的工程
  └─ M02 正确计算
       └─ M03 明确领域状态
            └─ M04 资源归属
                 └─ M05 访问授权
                      └─ M06 引用有效性
                           └─ M07 复用能力与接口
                                └─ M08 数据管线
                                     └─ M09 失败与诊断
```

## 每模块六节的固定角色

- **L01：引出矛盾**：从上一模块的产出提出一个上一模块无法充分解决的问题，解释为什么学当前模块。
- **L02：建立机制**：给出最小可验证模型。避免在解释之前堆术语和完整 API 列表。
- **L03：揭露边界**：以反例展示机制如何失败，并指出诊断与修正理由。
- **L04：工程化设计**：从局部知识推进到函数/模块/API 设计，比较至少两种方案。
- **L05：累积实验**：至少结合本模块前两节的能力，明确契约、失败测试、输入边界和本地验收方式。
- **L06：独立迁移**：更换业务情境，检查能否独立重用核心思路，最后抛出下一模块的需求。

这些是**教学角色**，不是机械更改现有课程标题或课程 ID 的指令。若某节现有知识安排不同，应调整叙事和练习衔接，而不是强行改变实际知识覆盖。

## 单节课程的可执行叙事链

1. **旧方法能做到什么**：用 1 个上一课已学的示例复习，不重新讲整个章节。
2. **旧方法在哪里失败**：展示一个具体需求、错误输出、编译诊断或维护成本。
3. **新机制如何解决**：只引入当下所需的最小 Rust 规则。
4. **用证据验证**：先让学生预测，再提供本地执行或编译检查方式与预期观察。
5. **边界与反例**：明确不适用情形、失败原因、替代设计及 Java/Go 对照（确实有帮助时）。
6. **改变原有工程**：把新能力加回实验或连续案例，避免形成另一段孤立知识。
7. **留下新问题**：简述下一课为什么必要，而不提前替学生解决。

推荐将“本节新增的设计决策”限制在一个主问题，其他概念作为支撑。不要为满足格式而复制同一句“实践迁移”到每节。

## 实施与验收

**阶段 A：路径显式化。** 模块首页、正文和导航显示“已有能力 → 新问题 → 本模块产出 → 下一步”；中英文结构一致。

**阶段 B：逐课叙事重写。** 优先消除 L01–L04 中的平行知识点条目，将例子改为相互依赖的问题序列。按照模块提交 PR，逐模块审查语义。

**阶段 C：实验闭环。** 审核 L05 是否真的依赖 L01–L04、L06 是否能脱离答案独立完成；保持 Rust 示例、现有公开契约、练习文件与链接正常。

**阶段 D：用户阅读检验。** 在桌面与手机检查读者能否在 30 秒内看懂“上一节学了什么、当前为什么学、下一节会做什么”；检查中英一致性、代码滚动、目录定位与导航信息密度。

每次修改必须执行仓库现有内容校验、TypeScript 检查及测试。阶段 A 不能当作所有 54 节已经完成深度重写。

## English summary

The published M01–M09 lessons form a single progressive capability: reproducible tooling → typed calculation → domain modelling → ownership → borrowing → lifetime contracts → traits → data pipelines → diagnosable errors. Every lesson must connect prior capability, a new concrete limitation, a minimal mechanism, evidence of mastery, and the next problem. Keep lesson IDs stable and align Chinese/English transitions. Do not represent a proposed shared project as an existing downloadable artifact.
