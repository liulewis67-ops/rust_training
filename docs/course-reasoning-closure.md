# 课程教学闭环检查（M01–M09）

本次质量增强在已发布的 54 节中文课程及 54 节英文课中，为每节加入具体的**原理推导与反例辨析**环节。它不是让所有课程共享一个业务案例，更不是把 M10 提前发布。

## 每节需要形成的因果链

1. **问题**：延续现有核心问题与场景，说明具体限制，不能写空泛口号。
2. **原理**：解释 Rust 的语义或工程约束，明确它与调用契约的关系。
3. **推导**：从该规则预测编译、运行或行为测试的结果。
4. **示例**：首先复用原先经过审查的 Rust 代码与模块实验，并说明从中应观察什么。
5. **反例**：改变一项关键条件，指出为何会产生编译错误、panic、错误输出或违反接口约定。
6. **练习**：要求先预测，再独立修改和验证；明确可观察的验收标准，而不仅是“尝试一下”。
7. **复盘**：让读者说明规则适用范围、设计取舍和错误解法为何不可取。

章节正文保留原有目标、原理、源码、实践迁移、实验与来源；新增的推导环节放在原有理解检查或实验验收之前，并非重复全部内容。

## 教学质量边界

- 不是所有反例都应编译失败；业务断言失败、错误结果、资源开销和未定义契约的误解都可以成为反例，但必须明确类别。
- 如果需要演示故意失败的代码，应先说明预期结果，并与可运行正例区分。
- Rust 的语言规则需区分编译期验证、运行时 panic、可恢复 Err 和工程性能猜测。
- 练习先给问题与验收条件，参考答案与提示保持已有位置和折叠机制。
- 中英文新增内容的含义须对应；保持已有 Rust fenced code 一致，避免破坏源码/练习资产测试。
- M01–M09 使用各模块最合适的案例；统一跨模块项目只属于未来 M10。

## 自动验证

新增 `src/content/course-reasoning-closure.test.ts` 约束 108 份双语课程中每节都有完整推理、反例、练习及复盘，内容应具备最低解释长度，并检查独立性与围栏配对。仓库已有的 course parity 与 module lesson tests 继续保护代码块及课程入口；这些静态检查不能替代实际 Rust 编译、教学人工审查或浏览器阅读体验检查。

建议运行：

```sh
pnpm content:validate-public
pnpm check:frontend
```

验收时再抽查不同模块的中英阅读页，以及实验的真实 Cargo 运行情况。记录未经执行的验证，不用“CI 将会通过”代替实际结果。
